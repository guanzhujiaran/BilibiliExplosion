# 个人中心「我的记录」系统计划书

> 状态：草稿
> 模块范围：前端（Vue3FrontEndDemoExercise）+ 后端（be-message-service）
> 关联规则：新增/修改功能需先改计划书再改代码；前端 SDK 变更需暂停等待用户重新生成

---

## 1. 背景与目标

现有「用户中心」仅有**用户中心首页**与**用户基本信息设置**两个菜单项。业务上需要用户能查看自己近期的**登录记录**与**经验（成长）记录**，以便核对账号安全与成长轨迹。

本计划书在现有用户中心基础上：
1. 新增一个左侧菜单栏「我的记录」，内置两个 tab：**登录记录**、**经验记录**。
2. 两个 tab 均**只展示最近一周**（7 天）的数据。
3. 后端新增对应的查询接口。
4. 前端在 SDK 重新生成后再实现（遵循 hey-api 规范）。

## 2. 现有功能盘点（接入前现状）

### 2.1 前端「用户中心」现状

用户中心布局 `src/views/UserCenterView.vue`，左侧菜单由 `user_center_routes` 渲染（`src/router/index.ts` 中定义，`export { user_center_routes }`）。

| 路由 name | path | 组件 | 说明 |
|-----------|------|------|------|
| `USER_CENTER_DASHBOARD` | ``（默认首页）| `UserCenterDefaultPanel.vue` | 用户中心首页：展示头像/等级/本系统账户/第三方 Casdoor 账户 |
| `USER_INFO_CONFIG` | `user-info-config` | `UserBaseInfoConfig.vue` | 用户基本信息设置：编辑昵称/签名/性别/生日 + 管理员角色授予 |

路由层级：`/app/user-center/`（`UserCenterView.vue`，`RouteName.USER_CENTER`）→ 子路由 `user_center_routes`。

`RouteName` 枚举位于 `src/models/router/index.ts`，已有 `USER_CENTER_DASHBOARD`、`USER_INFO_CONFIG` 等值，需新增「我的记录」相关值。

### 2.2 后端「用户中心」接口现状（be-message-service）

路由文件：`app/api/pptr_user_gateway.py`，前缀 `/api/v1/user`，鉴权依赖 `CurrentUser`（信任网关注入的 `x-bili-mid`，仅本人可查）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/nav` | 导航信息（含每日首次登录加经验、等级计算、邮箱脱敏）|
| GET | `/user_info` | 个人资料（用户基本信息设置回填）|
| POST | `/user_info/update` | 更新个人资料（昵称/签名/性别/生日）|
| POST | `/role/set` | 设置角色（仅 root）|
| GET | `/search` | 搜索用户（仅 root）|
| GET | `/casdoor/info` | Casdoor 完整信息（余额/积分等）|
| POST | `/logout` | 退出登录 |
| GET | `/identify` | 从 JWT 解析用户身份（网关中间件）|
| POST | `/refresh_token` | 刷新 JWT |
| GET | `/casdoor/callback` | Casdoor 登录回调 |

### 2.3 数据源现状（无需新增表）

登录/经验记录数据均已存在，由 be-message 接管/直连 pptr Postgres 库：

| 数据 | 表 | 模型 | 关键字段 | 写入方 |
|------|-----|------|---------|--------|
| 登录记录 | `TUserActInfoLog` | `PptrUserActInfoLog`（`app/models/pptr_db.py`）| `createdAt` / `mid` / `ip` / `ua` / `act_info`（`login_succ`/`reg`）| `casdoor_service.record_login_activity()`（Casdoor 登录回调）|
| 登录记录（每日首次访问） | 同上 | 同上 | 同上 | `PptrUserService.get_user_nav_data()`（本计划书新增）|
| 经验记录 | `TUserExpRecord` | `PptrUserExpRecord`（`app/models/pptr_db.py`）| `createdAt` / `mid` / `action_type` / `exp` / `ref_date` | `PptrUserService.add_exp()` / `add_daily_login_exp()` |

> 结论：**本功能无需新增表结构**，仅需新增两个只读查询接口，并补充「每日首次 nav 也算一次登录」的记录写入。

### 2.4 「每日首次访问也算登录」的判定

用户**已登录**状态跨天后，凌晨 12 点后首次调用 `GET /nav` 接口，会触发 `add_daily_login_exp()`（每日登录加经验，幂等）。该行为本质是「当天首次活跃 = 当天登录」，应同样记入 `TUserActInfoLog`，使登录记录能反映「每日凌晨后的首次访问」。

- 判定依据：复用 `add_daily_login_exp()` 的每日幂等逻辑——其返回 `can_add_exp=True` 即代表「今日首次登录」（当天 `TUserExpRecord` 尚无 `daily_login` 记录）。
- 写入点：`PptrUserService.get_user_nav_data()`（HTTP `/nav` 与 RPC `get_user_nav` 共用），接受可选 `ip` / `ua`（HTTP 入口从 request 提取，RPC 入口缺省为空串）。
- 与 Casdoor 登录回调的关系：Casdoor 回调（真实账号密码/第三方登录）走 `record_login_activity`（`act_info='login_succ'`）；每日首次 nav 走本逻辑。
- **`act_info` 取值区分**（避免与手动登录混在一起）：
  - 手动登录（Casdoor 回调）→ `login_succ`
  - **nav 每日首次登录 → `daily_login`**（与手动登录区分，前端可单独标注）
  - 注册 → `reg`

## 3. 功能设计

### 3.1 前端「我的记录」菜单

- 在 `user_center_routes` 中新增一条子路由（例：`USER_CENTER_RECORDS`，path `records`），指向「我的记录」页面组件。
- 页面内含 `el-tabs`，两个 tab：
  - **登录记录**
  - **经验记录**
- 数据仅展示最近 7 天。
- 菜单 icon / title 使用现有 `@element-plus/icons-vue` 图标 + i18n 文案。

### 3.2 前端「我的记录」页面

新增组件（参考现有 `UserBaseInfoConfig.vue` / `UserCenterDefaultPanel.vue` 写法），遵循 Vue + Tailwind + Element Plus 规范（无 `<style>` 块、使用语义化 class、默认/large 尺寸）。

**登录记录 tab**（对齐 B 站「登录记录」页形态）：
- 顶部标题：「登录记录 您最近一周的登录情况」
- 异常提示：根据登录时间 / IP / 地理位置，若判断为异常情况，请在核实后及时**修改密码**
- 固定说明（多条）：
  1. 移动端登录，运营商随机分配 IP，往往存在与实际登录地不符的情况
  2. 若使用 VPN 或代理联网，登录地无法准确记录
  3. 部分网络代理商的服务，存在 IP 地址不稳定的问题
  4. 使用哔哩哔哩账号登录的游戏，也存在一定程度的误报情况
- 表格四列：`时间`、`类型`、`IP`（脱敏）、`地理位置`（形如「中国上海移动」）
- **类型列单独标注**（依据 `act_info`）：
  - `login_succ` → 手动登录（如 `登录`）
  - `daily_login` → **每日登录**（nav 触发的每日首次访问，用不同 tag 类型区分，不与手动登录混淆）
  - `reg` → 注册

**经验记录 tab**：表格/列表展示 `时间`、`行为类型`、`经验变动`、`引用日期`。
- 分页加载（`offset + limit`），空态用 `el-empty`，加载态用 `el-skeleton` 或 loading。

### 3.3 后端新增接口

在 `pptr_user_gateway.py` 新增两个 GET 接口（鉴权 `CurrentUser`，仅本人）：

1. **登录记录**：`GET /api/v1/user/act-log`
   - query：`offset`(0 起)、`limit`(默认 10，最大 100)
   - 逻辑：查询 `TUserActInfoLog`，条件 `mid == 当前用户 uid` 且 `createdAt >= now - 7 天`，按 `createdAt` 倒序，`offset+limit` 分页。
   - **IP 脱敏**：用 `app/utils/ip_mask.py` 的 `mask_ipv4` / `mask_ipv6` 按协议打码（IPv4→`203.0.*.*`，IPv6→`2408:8207:*`）。
   - **地理位置**：用 `app/services/geo_ip.py` 的 `lookup(ip)` 实时解析，返回「地区 + 运营商」（如 `中国 上海 移动`）。`GeoIpResult.poi` 为省市区，`isp` 为运营商 ASN 名称，两者拼接为地理位置展示。解析失败返回「未知」。
   - 返回：`{ items: [{ time, ip(masked), location, ua, act_info }], has_more }`

2. **经验记录**：`GET /api/v1/user/exp-record`
   - query：`offset`、`limit`（同上）
   - 逻辑：查询 `TUserExpRecord`，条件 `mid == 当前用户 uid` 且 `createdAt >= now - 7 天`，按 `createdAt` 倒序，`offset+limit` 分页。
   - 返回：`{ items: [{ time, action_type, exp, ref_date }], has_more }`
   - `action_type` 为 int，需映射为可读文案（对齐 `app/models/enums.py` 的 `ExpActionType`，如 `1=daily_login`）。

### 3.4 数据模型（be-message 本地新增）

> 归属原则：**bili-common 只放会被多个服务共享的模型**；仅在本服务内部使用的模型一律放在各自系统里。
> 本功能的两个接口（登录记录 / 经验记录）仅 be-message 的用户中心使用、不对外共享、非 RPC 契约，因此**不放 bili-common**。

新增文件 `be-message-service/app/models/schemas/user_records.py`（参照 `schemas/` 下现有 `xxx.py` 组织方式，`__init__.py` 集中导出），参照现有 `Request/Resp` 命名约定新增：
- `UserActLogItem` / `UserActLogListResp`：
  - `time`（登录时间）、`ip`（脱敏 IP）、`location`（地理位置，地区+运营商）、`ua`、`act_info`
- `UserExpRecordItem` / `UserExpRecordListResp`：
  - `time`、`action_type`、`action_name`、`exp`、`ref_date`

服务层与路由层据此构造 `StandardResponse` 返回。

## 4. 接口详细约定

### 4.1 登录记录

```
GET /api/v1/user/act-log?offset=0&limit=10
Authorization: Bearer <JWT>
```

响应（`StandardResponse`）：
```json
{
  "code": 0,
  "msg": "",
  "data": {
    "items": [
      {
        "time": "2026-08-15T10:00:00+08:00",
        "ip": "203.0.*.*",
        "location": "中国 上海 移动",
        "ua": "Mozilla/5.0 ...",
        "act_info": "login_succ"
      }
    ],
    "has_more": false
  }
}
```

说明：`ip` 为脱敏后字符串（IPv4→`a.b.*.*`，IPv6→`a:b:*`）；`location` 由 `geo_ip.lookup()` 实时解析（地区 + 运营商），失败返回「未知」。

### 4.2 经验记录

```
GET /api/v1/user/exp-record?offset=0&limit=10
Authorization: Bearer <JWT>
```

响应（`StandardResponse`）：
```json
{
  "code": 0,
  "msg": "",
  "data": {
    "items": [
      {
        "time": "2026-08-15T10:00:00+08:00",
        "action_type": 1,
        "action_name": "daily_login",
        "exp": 5,
        "ref_date": "2026-08-15"
      }
    ],
    "has_more": false
  }
}
```

### 4.3 错误码

沿用 `bili_common.models.ResponseCode`：`0` 成功；用户不存在 `404`；未登录 `401`。

## 5. 开发顺序与分工

> 依据规则：先改计划书 → 实现后端 → 暂停等用户重新生成 SDK → 再编写前端。

1. **本计划书**（已完成）。
2. **后端实现**（be-message-service）：
   - `app/models/schemas/user_records.py` 新增 `UserActLogItem/ListResp`、`UserExpRecordItem/ListResp` 模型。
   - `PptrUserService` 新增两个只读查询方法（`list_act_log` / `list_exp_record`，带 7 天时间窗 + 分页）。
   - `pptr_user_gateway.py` 新增两个 GET 接口。
3. **暂停**：后端接口完成后，**需要更新 SDK**（openapi.json 新增 `/api/v1/user/act-log`、`/api/v1/user/exp-record`），停止等待用户手动执行 `npx @hey-api/openapi-ts` / vite build 重新生成 SDK。
4. **前端实现**（等 SDK 就绪后）：
   - `RouteName` 新增 `USER_CENTER_RECORDS`。
   - `user_center_routes` 新增「我的记录」子路由 + 菜单。
   - 新增「我的记录」页面组件（含登录记录/经验记录两个 tab）。
   - 封装 `moment-api.ts` 薄封装层调用新接口（不在 `hey-api/` 生成文件上改）。

## 7. 风险与注意事项

- 记录表数据量大时 7 天窗口查询依赖 `createdAt` 索引；`TUserExpRecord` 已有 `idx_exp_record_mid_action_ref_date` 索引。
- `TUserActInfoLog.headers` 为 JSON，仅展示时无需返回全量 header（接口只返回 ip/ua/act_info 精简字段）。
- 时间戳时区：统一使用数据库 `createdAt`（timezone-aware），前端按本地时区展示。
