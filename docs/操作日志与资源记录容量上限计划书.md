# 操作日志与资源记录容量上限 · 后端计划书

## 1. 背景

操作日志（`ActionLogRecord`）原本只有**时间滑动窗口**：`action_log_default_retention_days`
（默认 7 天）+ 每日清理任务。时间窗口只约束「多旧的数据该删」，约束不了「窗口内写进来多少」：
一次重负载工作流一天就能写进百万级步骤日志（每行还带 params / result / logs 等大 JSON 列），
7 天窗口内照样能把磁盘打满。

资源记录（`WorkflowResourceRecord`）是去重表，只增不减，没有任何清理机制。

因此两张表都补一个**固定行数上限**：超过上限后按时间列从旧到新删除，保留最新的
`max_rows` 行；时间窗口（日志）继续保留，两者取并集。

## 2. 规则

| 表 | 时间列 | 上限配置 | 触发任务 |
| --- | --- | --- | --- |
| `actionlogrecord` | `started_at` | `action_log_max_rows`（默认 2,000,000） | `action_log_cleanup`（默认每 24h） |
| `workflowresourcerecord` | `last_processed_at` | `resource_record_max_rows`（默认 2,000,000） | `resource_record_cleanup`（默认每 24h） |

- `0` = 不限制；负数按不限制处理。
- 保留口径：按时间列倒序（同时间按主键 id 倒序）的最新 `max_rows` 行，其余删除；
- 先按时间窗口删过期（仅日志），再执行行数上限，两步独立，任一步失败只告警；
- 分批删除（`record_cap_delete_batch_size`，默认 10,000 行/批）并逐批提交，
  避免一次删除百万行造成长事务锁表；
- 清理任务 `max_instances=1` + `coalesce=True`，不会叠跑。

实现：`app/utils/db_retention.py` 的 `trim_table_to_row_cap()`（与业务无关的通用裁剪，
Core 语句操作 `__table__`，不加载大 JSON 列）。

## 3. 资源记录的特殊说明

`WorkflowResourceRecord` 是执行去重的唯一依据：删掉某条记录 = 该资源会在下一次运行中
**重新被捞起处理**（可能重复点赞 / 重复参与抽奖，取决于业务动作）。

因此：

- 上限只是「防磁盘打满」的最后兜底，**不应设得比业务上还关心的历史窗口更小**；
- 删除按 `last_processed_at` 从旧到新，最近处理过的资源最后才会被删；
- 若某业务需要「永久不重复」，应把 `resource_record_max_rows` 调大或设为 0，
  而不是依赖容量清理。

## 4. 配置清单

`app/config.py`（环境变量同名大写）：

```env
action_log_max_rows=2000000
resource_record_max_rows=2000000
record_cap_delete_batch_size=10000
resource_record_cleanup_interval=86400
```

生产编排 `docker-compose.yml` 的 `rpa-browser` 环境段已同步这四个键；
`RPA-Browser/.env.example` 同步示例值。

## 5. 执行入口

`app/setup.py` → `register_background_tasks()`：

- `action_log_cleanup` 改为调用 `ActionLogCrudService.cleanup()`：
  `cleanup_expired()`（时间窗口）+ `enforce_row_cap()`（固定上限）；
- 新增 `resource_record_cleanup` → `ResourceRecordService.enforce_row_cap()`。

## 6. 验证

- 单测 `test/test_db_retention.py`：保留最新 N 行、分批删除、`max_rows=0` 不限制、
  未超限不删除（4 项）；
- 开发库实跑：`action_log_max_rows` / `resource_record_max_rows` 默认 200 万时
  两张表都返回 0（当前数据量远低于上限），时间窗口清理照常删除过期日志；
- 相关测试集 `test/execution_engine` + `test/controller` + `test/models` 共 232 项通过。
