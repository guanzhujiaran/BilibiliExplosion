# 工作流输入变量（WorkflowEditDialog）

## 背景

工作流是「调度外壳」：只引用一个复合动作（`custom_action_id`），步骤在动作里。
动作内的步骤通过 `{{变量名}}` 模板消费变量（`Scope.resolve_params`，strict 解析），
但这些变量的值在运行期从哪来，目前是断的：

- `run_workflow()` 构造 `WorkflowExecutionRequest` 时写死 `variables={}`、`input_data={}`；
- `UserWorkflow` 表没有变量值字段，创建/更新请求也没有；
- 结果：任何依赖 `{{变量}}` 的动作一旦被工作流引用，运行就会因变量未解析而失败，
  并且用户在「工作流编辑」里**找不到任何设置输入变量的地方**。

本次补齐「工作流级输入变量」：动作声明需要什么变量（契约），工作流里填值，运行期注入变量池。

## 设计

### 1. 数据模型（后端）

- `UserWorkflow.variables`：`JSON` 列，存**变量值**（`{name: value}`），默认 `{}`；
- 变量**定义**不落工作流：始终以引用动作为准（读时取），动作改契约后工作流界面自动跟随，
  避免定义副本过期：
  - 优先用动作的 `input_vars`（`InputVarDefinition`：name/type/required/default/description）；
  - 其 `input_variables`（`compute_custom_action_variable_contract` 计算的契约）补充
    未在 `input_vars` 里声明、但步骤里实际用到的变量（类型按契约，required 按契约）。

### 2. 接口

- `WorkflowCreateRequest.variables: dict = {}`、`WorkflowUpdateRequest.variables: dict | None`
  （`None` = 不修改，与其它字段一致）；
- `WorkflowDetailResponse.variables: Dict`，供编辑弹窗回显；
- 列表项不带变量值（避免列表响应变大）。

### 3. 运行期注入

`run_workflow` 前置阶段组装变量池：

1. 取被引用动作的变量声明，写入各自的 `default`；
2. 用 `workflow.variables` 覆盖（同名变量以工作流配置为准）；
3. 校验 `required` 变量：值为 `None` / 空串 → 抛 `WorkflowRunnerError`
   （走既有的「前置校验失败」路径：运行记录记 failed + 结束通知，不发车）。

组装结果传给 `WorkflowExecutionRequest.variables`，后续 `Scope` / 模板解析行为不变。

### 4. 前端（`WorkflowEditDialog.vue`）

- 新增「输入变量」配置区（位于「执行日志」之前、动作选择之后）：
  - 选择/回显动作时按 `action_id` 拉取动作详情（已有 `loadActionSummary` 接口），
    读取 `input_vars` + `input_variables` 合并成展示列表；
  - 每行：变量名（等宽）、类型标签、必填标（`*`）、说明（tooltip / 次行）、值输入；
    值输入按类型渲染：`string`→文本、`number`→数字、`boolean`→开关、
    `array/object`→多行 JSON 文本（保存前解析，非法 JSON 阻止保存并提示）；
  - 无输入变量时显示「该动作不需要输入变量」的空态；
  - 必填变量未填 → 表单校验不通过（与名称/动作/浏览器同一套 `canSave` 逻辑）。
- 保存：把值写入 `variables`（未填的非必填变量不写入，交给动作默认值兜底）；
- 回显：编辑态用 `workflowDetail.variables` 初始化；
- 切换引用动作时提示「输入变量已按新动作重置」，清空旧值（避免把 A 的变量带到 B）。

### 5. 依赖（SDK 同步）

新增 `variables` 字段改变了 OpenAPI，**需要重新生成前端 SDK**
（`npx @hey-api/openapi-ts` / 拉取新的 `openapi.json`）。

SDK 重新生成后，`WorkflowCreateRequest / WorkflowUpdateRequest /
WorkflowDetailResponse` 均已包含 `variables`，前端直接使用生成类型，
不再保留任何本地桥接类型或断言。

## 不做的事

- 不做「运行前临时填变量」（那属于 `workflows/run` 的入参扩展，后续迭代）；
- 不做变量引用下拉补全（契约计划书里已列为后续迭代）；
- 不改 `Scope` / 模板解析 / strict 语义。

## 验收

1. 动作声明 `input_vars`（含 required + default）后，工作流编辑里能看到对应输入项；
2. 保存后重新打开工作流，变量值正确回显；
3. 运行引用了必填变量但未配置的工作流：运行记录直接 `failed`，错误信息为
   「缺少必填输入变量: xxx」，且按 `notify_on_end` 发送失败通知；
4. 配置了变量值后运行：动作步骤里的 `{{变量}}` 能解析到值，不再因未解析失败；
5. `nuxt typecheck` 对改动文件无新增错误。
