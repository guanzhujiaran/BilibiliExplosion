# WebRTC 清晰度档位与自动降载（前端需求）

> 对应后端：RPA-Browser —— WebRTC 流清晰度档位（超清 / 高清 / 标清 / 流畅）与前端可见性驱动的自动降载。
> 计划书：`docs/be-message-统一计划书.md` §5.18
> 关联：§5.15 会话闲置生命周期（后端侧的自动降级）

## 1. 背景

原实现只有「正常 / 降级」布尔两档，且完全由后端闲置生命周期驱动（闲置降档、真实操作自动恢复）。
用户既不能主动选清晰度，前端把标签页切到后台时画面也仍按满帧编码传输，白白消耗 CPU / 带宽 / 电量。

## 2. 五个档位

| 档位 | 名称 | JPEG 质量 | 分辨率 | 帧率 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| `original` | 原画 | 100 | 页面真实视口（不缩放） | 30fps | 需要看清最细微的细节，带宽 / CPU 充裕 |
| `ultra` | 超清 | 90 | 1920×1080 | 30fps | 需要看清细节，带宽 / CPU 充裕 |
| `high` | 高清 | 80 | 浏览器自适应（≤800×800） | 30fps | 网络良好 |
| `medium` | 标清 | 65 | 960×540 | 15fps | 带宽一般 / 多路同看 |
| `low` | 流畅（**首次访问默认**） | 50 | 640×360 | 5fps | 弱网，仅需观察操作流程 |

> `original` 是**最高档（原画）**：JPEG 质量拉满（100），并且 screencast 显式按**页面真实视口尺寸**
> 采集 —— 浏览器侧默认会把画面等比缩放进 800×800，只有显式给出视口尺寸才是未缩放的原始图像。
> 代价是浏览器侧编码与网络带宽最高，仅建议单路观看时使用。

> `ultra` 把浏览器侧 screencast 的分辨率上限从「自适应 ≤800×800」抬到 1080p，
> 同时把 JPEG 质量提到 90。代价是浏览器侧编码与网络带宽显著上升。

> **切换档位不会断开或重建 WebRTC 连接**。后端通过重启 screencast 生效，画面自然衔接
> （切换瞬间可能丢 1~2 帧），前端**无需重连、无需重新 offer/answer**。

## 3. 新增接口

### 3.1 设置清晰度

`POST /browser/control/webrtc/quality`

请求：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `level` | `"ultra" \| "high" \| "medium" \| "low"` | 目标档位 |

响应 `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `level` | `string` | **用户档位**（本次设置值） |
| `effective_level` | `string` | **当前实际生效档位**——若此刻页面不可见或会话闲置，会低于 `level` |
| `degraded` | `bool` | 是否因自动原因（不可见 / 闲置）被降档 |

### 3.2 可见性信号

`POST /browser/control/webrtc/visibility`

请求：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `visible` | `bool` | `false` = 页面不可见（降档）；`true` = 恢复可见 |

响应 `data`：同 3.1（`level` / `effective_level` / `degraded`）。

### 3.3 暂停 / 恢复

`POST /browser/control/webrtc/pause`

请求：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `paused` | `bool` | `true` = 暂停发送视频；`false` = 恢复 |

响应 `data`：同 3.1，并额外含 `paused`。

**行为**：

- 暂停后**带宽与 CPU 归零**（后端停止 screencast，浏览器不再做 JPEG 编码）；
- 接收端画面**停留在最后一帧**（浏览器行为），不会黑屏；
- **不重建 WebRTC 连接**，恢复即时生效，无需重新 offer/answer；
- 暂停优先级**高于**清晰度档位，且不影响「取最省」的档位计算；
- 暂停是**会话级**状态：暂停期间切换页面（会重建流）后仍保持暂停。

**前端建议**：直播工具栏加「暂停 / 继续」按钮；暂停时明确展示暂停态，
避免用户误以为画面卡住或直播断了。

## 4. 「取最省」口径（重要）

生效档位由三个来源共同决定，**取最省的那一个**：

| 来源 | 触发方式 |
| --- | --- |
| 用户手动 | 调 `/webrtc/quality` |
| 前端可见性 | 调 `/webrtc/visibility`（标签页切后台 / 组件被遮挡时前端自动调） |
| 后端闲置 | 会话 120s 无真实操作（后端自动，见 §5.15） |

因此：

- 用户选了「高清」，**切后台仍会降到「流畅」**；
- 用户选了「高清」，**闲置 120s 后仍会被后端降到「流畅」**；用户重新操作会自动回到用户选的高清；
- 当 `effective_level` 与 `level` 不一致时，UI 应体现「当前因不可见 / 闲置临时降档」，而不是让用户以为选档没生效。

## 5. 前端交互要求

1. **清晰度选择器**：`LiveBox.vue` 提供档位切换（原画 / 超清 / 高清 / 标清 / 流畅），切换后立即调 `/webrtc/quality`，
   并以响应的 `effective_level` 为准刷新 UI——**不要在本地"假成功"**。
2. **档位记忆（新增）**：用户选定的档位记入 `localStorage`，下次进入直播时**自动沿用上次的选择**；
   - **首次访问（localStorage 中没有记录）默认「流畅」`low`**，而不是高清 —— 先按最省带宽的口径起步，
     由用户按需上调；
   - 仅记忆**用户手动选择**的档位（`level`），**不要**把「自动降档」后的 `effective_level`
     写进本地存储，否则用户切后台一次就会被永久记住成低档；
   - 读写需 `try/catch` 兜底（隐私模式等场景下 localStorage 可能不可用），失败时退化为默认档。
3. **未开流时的行为**：后端在流未运行时仅记录目标档位、下次开流生效；前端应禁用选择器或提示「开流后生效」。
4. **自动降载**：`LiveBox.vue` 需同时监听两类不可见，**任一不可见**即调 `/webrtc/visibility` 且 `visible=false`，
   **全部恢复可见**才 `visible=true`：
   - `document.visibilitychange` → `document.hidden`；
   - `IntersectionObserver` 观察 LiveBox 根元素（覆盖 `el-splitter` 折叠、被弹层遮挡、滚出视口）。
5. **卸载 / 停流复位**：组件 `onUnmounted` 或主动停流时，若此前发过 `visible=false`，需补发 `visible=true`，
   避免残留状态把后续新流压在低档。
6. **提示降档原因**：`degraded=true` 时给出轻提示（如「已自动降为流畅以节省带宽」），
   避免用户误以为是自己选的档位没生效或画面出了问题。
