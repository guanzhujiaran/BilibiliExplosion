# 运行记录执行批次入口 & 操作日志统计口径

## 1. 工作流运行记录：显示执行批次，点击跳「已处理数据」

- 位置：`RPA 浏览器 → 工作流管理 → 某工作流 → 运行记录` 弹窗（`WorkflowRunLogDialog`）。
- 表格新增「执行批次」列（在「目标浏览器」之后），展示 `execution_id` 前 8 位：
  - 有批次：等宽字体链接，`tooltip` 显示完整批次号与「查看该批次已处理数据」；
  - 无批次（如运行记录未落批次）：显示 `-`，不可点击。
- 点击行为：关闭运行记录弹窗，跳转「已处理数据」页并带上
  `?workflow_id=<当前工作流>&execution_id=<批次>`。
- 语义依据：运行记录的 `execution_id`、资源记录的 `execution_id`、操作日志的
  `execution_id` 三处同值，无需映射。

## 2. 已处理数据页：支持 `?execution_id=` 定位批次

- 「已处理数据」页读取 URL 的 `workflow_id` / `execution_id`：
  - `workflow_id`：选中对应工作流（原有能力）；
  - `execution_id`：页面顶部显示「执行批次」过滤条（含完整批次号与「清除批次筛选」），
    同时把值写进表格「执行批次」表头筛选框并立即查询，地址栏与筛选框始终一致。
- 清除批次筛选：同步删掉地址栏的 `execution_id`，避免刷新后又回到过滤态。
- 刷新 / 分享链接 / 从运行记录再次跳转（同路由复用组件）都要重新应用 URL 条件。

## 3. 操作日志页：统计必须跟随筛选口径

- 问题：`/app/rpa-browser/action-logs` 顶部「总操作 / 成功 / 失败 / 成功率」原先固定按
  「近 7 天 + 全量」统计，完全不看当前筛选。带 `execution_id` 从「已处理数据」跳进来时，
  列表只有十几条，概览却仍是全量上万条，数字对不上。
- 期望：
  - 统计接口与列表接口吃同一组筛选条件（操作ID / 批次 / 工作流 / 浏览器 / 来源 / 状态 /
    结果 / 关键字）；
  - 时间口径与列表一致：默认不限时间（`days=0`，日志本身有保留期），不额外叠加时间窗；
  - 查询、重置、清除批次筛选、地址栏批次变化时，列表与统计一起刷新；
  - 卡片文案：有生效筛选时首卡显示「匹配操作」，无筛选时显示「总操作」；
    成功率 = 成功 / 总数。
- 验收：任一筛选（尤其 `?execution_id=`）下，卡片「匹配操作」数字与列表「共 N 条」一致。
