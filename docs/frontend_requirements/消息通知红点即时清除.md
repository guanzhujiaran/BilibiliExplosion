# 消息空间通知红点即时清除

## 背景

消息中心 `/app/message/notify`（`NotifyListView.vue`）被 `MessageLayout` 的 `<keep-alive>` 缓存，
`onMounted(handleLoad)` 只在**首次挂载**执行。后端是「读取即已读」：`GET /notify/list` 在返回前把
本页通知批量置为已读，前端加载完成后再 `emit('refreshUnread')` 刷新未读汇总。

问题链路：

1. 首次进入通知页 → 列表加载 → 本页标已读 → 红点清零（正常）；
2. 离开通知页（组件被 keep-alive 缓存）；
3. 期间新通知到达，`MessageLayout` 的 60s 心跳把未读数刷出来，红点重新出现；
4. **再次点击「通知」进入**：`onMounted` 不再执行，列表不重新拉取 →
   服务端「读取即已读」不触发 → 红点一直停留在心跳拉到的那次数值。

用户观感就是「点开查看消息后，数量红点没有立刻消失」。

## 需求

1. 进入通知页（含从其它子页切回）时，若存在未读，立即重新拉取第一页，让服务端落库已读并把红点清零；
2. 空列表也要刷新未读汇总（本地红点可能来自上一次心跳/缓存，不刷新会一直残留）；
3. 未读汇总的并发请求以**最后发出**的那次为准，避免先发后到的旧结果把刚清零的红点写回去。

## 方案

- `NotifyListView.vue`
  - `handleLoad` 成功后**无条件** `emit('refreshUnread')`（原实现仅在 `pageItems.length > 0` 时触发）；
  - 新增 `onActivated`：跳过首次（`onMounted` 已负责），之后只要 `notifyUnread > 0` 就重置分页并重拉首页。
- `MessageLayout.vue`
  - `refreshUnread` 增加自增序号，仅接受最新一次响应，消除「心跳刷新」与「页面读取即已读」
    两次请求的乱序覆盖。

## 全清口径（2.71.0）

后端用户侧 `GET /notify/list` 在返回本页之后，会调用 `NotifyService.mark_all_read` 把该用户
**全部可见未读**通知一并置为已读（判定条件与 `msg_feed/unread` 的 `notify` 完全一致）。
因此「一进通知页就全清」不再受 `page_size`（默认 20）限制，也不新增接口、不需要重新生成 SDK：

- 前端加载完成 → `emit('refreshUnread')` → `msg_feed/unread` 返回 `notify=0` → 红点归零；
- 出参 `is_read` 仍是**读取前**快照，本次新到的通知仍可高亮；
- `/notify/system`（B 站形态）与 `/notify/pull` 不触发全清，保持原语义。

## 验收

- 停留其它页面收到新通知（红点出现）→ 点「通知」→ 红点立即消失，列表顶部出现新通知；
- 离开消息中心再回来（组件从缓存恢复）→ 有未读就刷新，无未读不重复请求；
- 通知列表为空的账号进入页面 → 红点同样被刷新为 0，不会残留；
- 心跳与页面刷新并发时，红点不会出现「先清零又跳回旧值」的闪烁。
