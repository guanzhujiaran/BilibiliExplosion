# 热门抽奖面板拆出「第三方动态」榜

## 背景

首页热门抽奖面板（`HotLotteryList.vue`）当前只有两个 Tab：`site`（本站热门）与 `bili`（B站热门）。

`site` 口径只聚合 `TInteractionViewLog` 里 `bizType=lottery`（官方 / 预约 / 充电抽奖）的浏览记录，
而第三方抽奖动态的浏览记在 `bizType=others_lot_dyn`（`bizType=15`，bizId 是 B 站动态 `dynId`）。
两者是**独立命名空间**（id 语义、卡片形态都不同），既不能共用一张卡片渲染，也不能混在一个榜里排序，
结果就是第三方动态的浏览热度无处体现。

本次把第三方动态单独拆成一个榜单 Tab，**不做聚合**。

## 需求

1. 热门抽奖面板改为三个 Tab：
   - `本站抽奖`（`rank_by=site`）：官方 / 预约 / 充电抽奖，按近 N 天去重浏览人数降序；
   - `第三方动态`（`rank_by=site_third`）：第三方抽奖动态，按近 N 天去重浏览人数降序；
   - `B站热门`（`rank_by=bili`）：按 crawler 抓取时参与人数降序（口径不变）。
2. 三个 Tab 共用同一套卡片列表组件（`BiliLotterySimpleList`），卡片形态由后端下发的 `card` 决定：
   - `site` / `bili`：抽奖卡片 `{raw, extra_info}`（`normalizeLotteryData` → 官方/预约/充电）；
   - `site_third`：第三方动态 item（含 `dynId` / `dynamicUrl` / `extra_info`，`normalizeLotteryData` → `THIRD_PARTY`）。
3. 统计口径标签随 Tab 变化：前两个显示「近 N 天浏览人数」，`bili` 显示「抓取时参与人数」。
4. 第三方动态卡片点击「查看详情」进入站内详情页（`OTHERS_LOT_DYN_DETAIL`），「查看源动态」仍跳 B 站外链；
   互动态批量拉取沿用现有 `lotteryCardInteractionTargets`（内部已按 `THIRD_PARTY` 分到 `bizType=15`），**无需改动**。
5. 空态文案可按口径区分（如「近 N 天暂无浏览数据」），不做前端截断与兜底造数。

## 后端接口（已完成）

`GET /api/v1/community/interaction/hot-lotteries?rank_by=site|site_third|bili&window_days=&limit=`

- `rank_by=site_third` 返回 `HotLotteryItem[]`，其中 `card` 为 `OthersLotDynCard`
  （字段：`dynId` / `dynId_str` / `dynamicUrl` / `authorName` / `up_uid(_str)` / `pubTime` /
  `dynContent` / `commentCount` / `repostCount` / `likeCount` / `officialLotType` /
  `created_at` / `isManualReply` / `extra_info`）。
- `HotLotteryItem.card` 类型变为 `LotteryCard | OthersLotDynCard`；同一次响应里只会出现其中一种。
- 卡片经 crawler 只读查询服务 `GetOthersLotDynDetailList` 批量回捞，取不到卡片的项服务端已剔除，
  前端仍需保留 `filter(Boolean)` 防御。

## 前端改动（待 SDK 重新生成后执行）

> `rank_by` 的取值集合与 `HotLotteryItem.card` 的类型都变了，属于 **SDK 契约变更**：
> 必须先重新生成 `src/api/**/hey-api/`，**不允许手改生成文件**，也不允许用 `as any` 绕过类型。

1. `src/api/notify/moment-api.ts`：`HotLotteryRankBy` 扩为 `'site' | 'site_third' | 'bili'`
   （SDK 重新生成后由生成类型驱动，必要时以交叉类型补齐，不改 `hey-api/`）。
2. `src/components/lottery_data/bili_data/HotLotteryList.vue`：
   - 增加第三个 `el-radio-button`（`value="site_third"`，文案「第三方动态」）；
   - `details` 类型由 `LotteryCard[]` 改为 `AnyLotteryData[]`（或 `LotteryCard | OthersLotDynCard` 联合）；
   - `recentViewerMap` 逻辑不变（`recentViewCount` 三种口径都有值，`bili` 为 0）；
   - `show-participants` 仅 `rank_by=bili` 为 `true`；
   - 切换 Tab 时重新拉榜（现有 `watch(rankBy)` 已覆盖）。
3. `src/components/lottery_data/bili_data/BiliLotterySimpleList.vue` 的 `data` 已是 `any[]`，
   第三方卡片无需新增分支；确认「第三方动态」Tab 下不展示「参与人数」。

## 验收

- 三个 Tab 分别请求 `rank_by=site` / `site_third` / `bili`，参数与标题、口径标签一致；
- 登录用户浏览过第三方动态详情或点过其「查看源动态 / 抽奖详情」后，`site_third` 榜能出现该卡片，
  且它**不会**出现在 `site` 榜；
- 第三方卡片标题为「xxx 的抽奖动态」、点击「查看详情」进入站内详情页，不出现空壳卡片；
- crawler 只读查询服务不可用时，`site_third` 返回空数组，前端只展示空态、不报错。
