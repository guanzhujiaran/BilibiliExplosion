# 浏览器详情页与「关联的工作流」

> 关联计划书：`docs/rpa-workflow-调度外壳计划书.md` 第 8 章

## 背景

工作流列表卡片（`src/views/rpa-browser/WorkflowManagement.vue`）已展示「目标浏览器」标签
（`browser_id` + 浏览器名称映射）。用户需要从工作流侧反查浏览器：点击标签进入浏览器详情页，
并在详情页看到「这个浏览器被哪些工作流引用」。

## 后端契约变更（RPA-Browser）

`POST /api/v1/rpa/browser/control/workflows/list` 的请求体 `WorkflowListRequest` 新增可选字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `browser_id` | `int \| null` | 按执行目标浏览器过滤；不传不过滤。与既有 `filter_type` 条件叠加 |

- `filter_type: 'all'` + `browser_id: X` ⇒ 当前用户名下 `browser_id = X` 的工作流（公开 + 私有）。
- 响应结构不变（`BasePaginationResp[WorkflowListItemResponse]`）。

## 前端需求

### 1. 新路由与页面

- 路由：`detail/:browserId`，`RouteName.RPA_BROWSER_DETAIL = '浏览器详情'`，组件
  `src/views/rpa-browser/BrowserDetail.vue`（顶层路由组件，模板单根）。
- 页面结构：
  - `BiliPageHeader`：标题为浏览器名称（加载完成前显示「浏览器详情」），右侧「返回」按钮回指纹列表页；
  - 基本信息区：名称 / Browser ID / 浏览器 / 平台 / 平台版本 / 浏览器版本 / 代理 / 创建时间 / 更新时间，
    数据源为 `readFingerprintRouter...`（`query: { browser_id }`）；
  - 关联工作流区：调用 `listWorkflows...`（`filter_type: 'all'` + `browser_id`），展示
    触发方式（手动 / 定时 + cron）、启用状态、上次运行状态；无关联工作流时展示空态。
- 规则：无 `<style>` / `:style`；语义化 class（`browser-detail` / `browser-detail__info` /
  `browser-detail__workflows`）；工作流列表内部滚动用 `BiliScrollbar` + `el-pagination` 吸底。

### 2. 工作流卡片入口

- `WorkflowManagement.vue` 的 `workflow-card__browser` 标签可点击（`cursor-pointer`），
  点击跳转 `{ name: RouteName.RPA_BROWSER_DETAIL, params: { browserId: String(item.browser_id) } }`。

### 3. SDK 重新生成（已完成）

后端 `WorkflowListRequest` 新增 `browser_id` 后，`src/api/browser/hey-api/` 已重新生成：
`WorkflowListRequest` 含 `browser_id?: number | null`。`BrowserDetail.vue` 的关联工作流请求
（`filter_type: 'all'` + `browser_id`）已使用正式类型，无临时 cast。

## 验收

1. 点击工作流卡片的目标浏览器标签 → 进入 `/app/rpa-browser/detail/{browserId}`，信息展示正确。
2. 「关联的工作流」只包含 `browser_id` 指向该浏览器的工作流；为空时展示空态。
3. 分页 / 滚动行为符合「滚动条与分页布局」规范（页面整体不滚，仅列表内部滚）。
4. `npm run check:route-root` 通过（详情页为顶层路由组件，单根）。
