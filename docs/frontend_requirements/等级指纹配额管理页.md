# 等级指纹配额管理页（前端需求）

> 对应后端：RPA-Browser —— 各等级「最大浏览器指纹数量」的管理端配置（落盘 `app/data/permissions.json`）。
> 计划书：`docs/be-message-统一计划书.md` §5.19
> 关联：§5.14 RPA 浏览器实例监管、`verify_fingerprint_limit`（业务码 2008）

## 1. 背景

各等级能创建多少个浏览器（= 浏览器指纹）」原先只能手工改服务器上的
`RPA-Browser/app/data/permissions.json`，没有接口、没有界面；而该文件在容器内属于源码挂载目录，
误删/重建即回到默认值。本次提供管理端查询 + 修改能力，改完直接写回该文件。

## 2. 权限与可见性

- **仅消息管理端 root 可访问**（后端 `require_root` 强制；前端仅做显隐/拦截）。
- 路由 `requiresMessageRoot: true`（非 root 访问伪装 404，与 `ADMIN_SYS_CONFIG` 一致）。
- 侧边栏挂在 **「系统设置」** 组（该组已是 root 专属），菜单名 **「浏览器配额」**。
- 接口与权限位（`msg_admin.biz_perms`）无关，RPA 管理员亦不可改。

## 3. 接口

### 3.1 查询等级配额

`GET /api/admin/rpa/permission/levels`

响应 `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `levels` | `PermissionLevelQuota[]` | 各等级配置（顺序即磁盘顺序） |
| `config_file` | `string` | 实际读写的配置文件路径（展示用，便于运维定位） |

`PermissionLevelQuota`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `level_name` | `string` | 等级名，如 `level0` / `level6` / `root` |
| `level_value` | `int` | 等级值（`root` 为 99） |
| `permissions` | `int[]` | 该等级的功能权限位（**只读展示**，本页不改） |
| `max_fingerprints` | `int` | 该等级允许创建的最大浏览器指纹数量（**本页唯一可编辑字段**） |

### 3.2 保存等级配额

`POST /api/admin/rpa/permission/update`

请求：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `levels` | `{ level_name: string; max_fingerprints: int }[]` | 需要更新的等级（只需传被改动的等级） |

- `max_fingerprints` 必须 ≥ 0，否则后端 400（不入库、不落盘）。
- `level_name` 必须是磁盘上已存在的等级，否则后端 400。
- **`permissions` / `level_value` 不接受前端传值**：后端按 `level_name` 合并进磁盘现值后整体写回，
  即使用前端臆造这两个字段也不会生效。

响应 `data`：与 3.1 同构的**全量** `levels` + `config_file`（保存后以服务端为准，前端直接覆盖本地状态）。

### 3.3 恢复默认配额

`POST /api/admin/rpa/permission/reset`

无请求体。把 `permissions.json` 整体恢复为后端代码内的 `DEFAULT_CONFIG`（同样仅 root），响应同 3.1。

界面要求：提供「恢复默认」按钮，**必须二次确认**（提示会把所有等级配额恢复为代码默认值），成功后以返回的全量数据刷新表格。

## 4. 界面要求

- 页面为**单根组件**（顶层路由组件规则），无 `<style>` 块、无内联 `:style`，样式全部走 Tailwind 语义类。
- 结构：页头（标题「浏览器配额」+ 说明「仅 root 可见，改完即写入配置文件，立即生效」+ 刷新按钮）
  → 配置文件路径提示（`el-alert` 或说明文本）
  → 等级表格 → 保存/重置按钮。
- 表格列：等级名（带 `level_value`）、功能权限位（只读，标签形式展示，`root` 档显示「不受限制」）、
  **最大指纹数量（`el-input-number`，`min=0`，大号尺寸，不做上限截断）**、当前已用（可选）。
- 未保存改动时，「保存」按钮可用；`root` 档建议给出提示（`999999` 视作不受限制）。
- 保存成功/失败用统一 `biliMessage` 提示；失败展示后端 `msg`。
- 图标：菜单项使用 `src/assets/svgs/` 下已有资源（见 `icons.mdc`），不引入 Element Plus 图标。

## 5. SDK 说明

RPA 侧 browser hey-api SDK（`src/api/browser/hey-api/`）为生成代码、**禁止手改**。
SDK 已重新生成，三个接口均已生成到 `管理员管理Service`：

| 接口 | 生成函数 |
| --- | --- |
| `GET /permission/levels` | `readPermissionQuotasApiAdminRpaPermissionLevelsGet` |
| `POST /permission/update` | `updatePermissionQuotasApiAdminRpaPermissionUpdatePost` |
| `POST /permission/reset` | `resetPermissionQuotasApiAdminRpaPermissionResetPost` |

前端封装层（`src/api/browser/permission_api.ts`）直接调用上述生成函数，类型取自生成产物
（`PermissionQuotaResp` / `PermissionQuotaUpdateReq` / `PermissionLevelConfig`），
不再有任何手写 URL。
