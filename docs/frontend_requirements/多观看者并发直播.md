# 多观看者并发直播（前端需求）

> 对应后端：RPA-Browser —— WebRTC 流的「帧源 / 观看者」解耦。
> 关联计划书：`docs/rpa-多观看者并发直播计划书.md`。
> 接口统一前缀：`/api/v1/rpa`（下文省略），WebRTC 相关接口挂在 `/browser/control/webrtc` 下。

## 1. 背景

同一账号在同一 `browser_id` 上多端打开时，现状是**互相抢同一条 WebRTC 流**：

- 后开的一端会**淘汰**先开的一端的流（后端按 `page_index` 唯一）；
- 被淘汰的一端前端看门狗（8s 无字节）会**自动重连**，于是又把另一端踢掉 → **互踢死循环**；
- 更隐蔽的是 `stream_key` 不含观看者标识，先开的端延迟补发的 answer / ICE 候选会**打到后开的流上**，
  导致两端都连不上（表现为 ICE 永远 `checking`、黑屏）；
- 暂停 / 清晰度是**会话级**，A 暂停会让 B 也停。

后端改为「**一份帧源 + 每条连接一个观看者**」后：

- 多端可**同时观看**，互不影响；
- **暂停 / 清晰度 / 可见性降档变为「观看者级」**（各自独立）；
- **切页 / 新建页 / 关闭页仍是「会话级」**（改的是浏览器本身，物理上无法按端隔离）。

## 2. 能力分层（前端必须理解的核心变化）

| 能力 | 作用域 | 说明 |
| --- | --- | --- |
| 暂停 / 继续 | **观看者级** | A 暂停只影响 A 自己的画面，B 继续播放 |
| 清晰度档位 | **观看者级** | A 选流畅只影响 A；分辨率由服务端**按 A 的档位缩放**后单独编码 |
| 可见性降档 | **观看者级** | A 的标签页切后台只降 A，不拖累 B |
| 在线人数 | 会话级 | 展示「当前 N 人在观看」 |
| 切换页面 / 新建页 / 关闭页 | **会话级** | 一端操作，其余端跟随（画面切到同一页） |
| 关闭浏览器会话 | 会话级 | 会话销毁，所有端同时下线 |

## 3. 接口变更

### 3.1 `viewer_id`（本次最重要的约定）

前端在**每次建立 WebRTC 连接时**生成一个观看者标识：

```ts
const viewerId = crypto.randomUUID()
```

- **必须存在组件内存中**，用于该次连接的所有信令与播放控制请求；
- **不要存 `localStorage`**（多标签会串成同一个 id）；
- **不要存 `sessionStorage`**（浏览器「复制标签页」时会被一起复制，同样会串）；
- 刷新页面即换新 id，旧 id 由后端 60s 心跳超时回收兜底。

所有下述请求的 body 都需带上 `viewer_id`。

### 3.2 端点一览

| 端点 | 变更 |
| --- | --- |
| `POST /webrtc/offer` | body 增加 `viewer_id`；**不再淘汰**同页其他观看者的流；返回的 `stream_key` 尾部带观看者标识 |
| `POST /webrtc/answer` | body 增加 `viewer_id` |
| `POST /webrtc/ice-candidate` | body 增加 `viewer_id` |
| `POST /webrtc/close` | body 增加 `viewer_id`；**只关自己这一路**，不影响其他端 |
| `POST /webrtc/pause` | body 增加 `viewer_id`；返回**本端**档位快照 |
| `POST /webrtc/quality` | body 增加 `viewer_id`；返回**本端**档位快照 |
| `POST /webrtc/visibility` | body 增加 `viewer_id`；返回**本端**档位快照 |
| `POST /webrtc/heartbeat` | **新增**：body `{viewer_id}`；观看者保活 |
| `POST /webrtc/status` | `data` 增加 `viewer_count` 与 `viewers[]`（见 §3.3） |

`stream_key` 仍由前端**原样透传**（answer / ice / close 都带上后端返回的那个值），前端不需要解析它。

### 3.3 `POST /webrtc/status` 响应

```json
{
  "code": 0,
  "data": {
    "enabled": true,
    "total_streams": 2,
    "viewer_count": 2,
    "viewers": [
      { "viewer_id": "…", "page_index": 0, "state": "active",
        "paused": false, "level": "high", "effective_level": "high", "idle_seconds": 3.2 }
    ],
    "active_streams": [ /* 兼容字段，保留 */ ]
  }
}
```

### 3.4 保活：`POST /webrtc/heartbeat`

- **用途**：证明「这个观看者还在线」，后端据此**不把会话判定为闲置**（否则会降级 / 挂起）。
- **频率**：每 15s 一次，**复用已有的 1s 网速采样定时器计数**，不要新增定时器。
- **停止时机**：用户主动停止直播、组件卸载、连接失败时立即停止发送。
- 失败是**静默**的（不弹提示）：它属于后台保活。

> 注意：**`/webrtc/status` 不保活**（它是只读接口）。不要在 `loadWebrtcStatus()` 里顺带发心跳，
> 也不要把两者混在一起，否则「看一眼状态」就会把闲置回收打穿。

### 3.5 会话状态 SSE 的 `viewer_count`

`session_status` 事件的 `data` 增加 `viewer_count` 字段，人数变化会被即时推送。
前端用它渲染在线人数提示，**不需要为此新增轮询**。

## 4. 前端交互要求

1. **`initWebRTC()` 生成 `viewerId`**：每次调用（含自动重连、切页重连）都生成**新的** `viewerId`，
   并在该次连接的 offer / answer / ice / close 请求中带上。
2. **暂停语义修正**：`handleTogglePause()` 现在是**本端**暂停。
   - 文案与注释去掉「会话级」表述；
   - 暂停后本端画面定格，**不再影响其他端**；
   - 提示语避免出现「已为所有人暂停」这类误导。
3. **清晰度语义修正**：`handleSetQuality()` 只改本端。
   后端返回的 `effective_level` 是**本端**的生效档位（可能因本端不可见而降档），
   仍按现有 `applyQualitySnapshot()` 逻辑处理即可。
4. **可见性上报带 `viewer_id`**：`reportVisibility()` 的请求体增加该字段，语义不变（尽力而为、失败静默）。
5. **`loadWebrtcStatus()` 判定「我是否在直播」**：
   **不能再用 `total_streams > 0`**（多人观看时会被别人的连接数误导），
   应改为在 `viewers[]` 中查找 `viewer_id === 当前 viewerId` 且 `state === 'active'`。
6. **在线人数展示**：
   - 数据来源优先 `viewer_count`（来自 SSE 推送）；
   - `viewer_count >= 2` 时展示提示（如「2 人在观看」），单人时可隐藏或显示「1 人在观看」；
   - 建议同时说明「暂停 / 清晰度仅影响你自己的画面」，降低多人使用时的困惑。
7. **`isPaused` 的事件上抛**：仍可保留 `emit('paused-change')`，但注释应更正为**本端状态**
   （原文写的是「会话级状态」，已不成立）。
8. **切页 / 关页行为不变**：仍是会话级操作，操作后按现状重连自己的流（此时应生成**新的 `viewerId`**）。
9. **停止直播**：`handleStopStream()` 调用 `/webrtc/close` 时带 `viewer_id`，
   并**立即停止心跳**（避免已关闭的观看者继续续命）。

## 5. 错误与边界

| 场景 | 期望表现 |
| --- | --- |
| 多端同时开播 | 两端都有画面；不应出现「一端连上、另一端黑屏」 |
| 心跳失败（网络抖动） | 静默忽略，下一次心跳照常；不弹提示、不中断播放 |
| 观看者已被后端回收（如 60s 无心跳后恢复网络） | answer / ice 返回业务码 `WEBRTC_STREAM_NOT_ACTIVE`；此时应走**重新建流**（生成新 `viewerId` 重新 offer），而不是无限重试旧 `stream_key` |
| `close` 返回流不存在 | 视为已关闭（幂等），不弹错误提示 |
| 另一端暂停 / 切档 | 本端**无任何变化**（不得因为别人的操作触发本端重连或画面变化） |
| 另一端切页 / 关页 | 本端画面跟随变化；若目标页被关闭导致本端流失效，按「重新建流」处理 |
| 同一 `viewerId` 重复 offer（本端重连竞态） | 后端复用并重建该观看者，前端按正常流程处理返回值即可 |
| 监管只读页（`AdminBrowserMonitorView`） | 与现有约定一致：不订阅 SSE；如需观看视频，同样需要自己的 `viewer_id` |
