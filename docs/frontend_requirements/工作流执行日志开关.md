# 工作流执行日志开关（WorkflowEditDialog）

## 背景

工作流（调度外壳）执行后，`POST /api/v1/rpa/browser/control/action-logs/list` 一直为空：
步骤日志采集受三级开关控制，默认全关，用户侧没有任何入口可以打开。

本次把「是否记录执行日志」下沉为**工作流维度的一个开关**，与触发配置、运行通知同级；
同时全局保留策略收紧为 7 天并落地周期清理（后端侧，见 `docs/rpa-workflow-调度外壳计划书.md` §9）。

后续增量（2026-10-25）：同区新增**调试模式**开关（用户级 debug，后端设计见
`docs/rpa-workflow-调度外壳计划书.md` §9.8）——一个开关把采集强度拉到最满，
用于排查问题；保留期与普通日志一致（仍是 7 天）。

采集优先级（后端，三态开关：`true`=显式开 / `false`=显式关 / `null`=未设置听从下一级）：

1. 执行参数 `log`（单次执行某步骤）
2. **工作流调试模式** `UserWorkflow.log_debug`（优先于工作流开关，debug 隐含开启）
3. **工作流开关** `UserWorkflow.log_enabled`（本次运行总闸）
4. **动作开关** `CompositeActionModel.log_enabled` / `log_debug`
5. **项目兜底** `settings.action_log_default_enabled`

## 前端需求

### 1. 新增「执行日志」配置区

位置：`src/components/rpa-browser/WorkflowEditDialog.vue`，放在「运行通知」区之后、
底部提示 `el-alert` 之前，与其它配置区同款 bordered 卡片容器（`workflow-log-section`）。

内容：

- 区标题「执行日志」+ 一行说明：开启后按步骤记录入参 / 返回结果 / 耗时，可在「运行记录」中
  按执行批次下钻查看；日志仅保留最近 7 天，超期自动清理。
- `el-switch`（default 尺寸，`inline-prompt`，active-text「开」/ inactive-text「关」）绑定
  `logEnabled`，label「记录执行日志」。
- 开关旁动态提示：开 → 「日志仅保留最近 7 天，超期自动清理」；
  关 → 「关闭后本次运行不记录任何步骤日志」。

### 1.5 调试模式开关（同区第二行）

- `el-switch`（同款尺寸与 `inline-prompt`）绑定 `logDebug`，label「调试模式」，
  放在「记录执行日志」下方同一分组内（`workflow-log-section__debug`）。
- 说明文案（动态）：
  - 开 → 「全量记录：入参 / 返回结果 / 变量池快照全部记录，成功的步骤也记录，
    内容不截断；用于排查问题，日志量更大（仍只保留 7 天）」；
  - 关 → 「关闭后按上方开关的常规强度记录」。
- **耦合规则**：打开调试模式时自动把 `logEnabled` 置为 `true`（debug 隐含开启，
  后端也是如此判定的）；关闭调试模式**不影响** `logEnabled`（用户可能只想
  关调试、保留常规记录）。
- 关闭「记录执行日志」时调试模式无意义，但不强制关闭（后端以 debug 优先，
  会出现「记录关 + 调试开 → 仍全量记录」）；为避免困惑，`logEnabled` 关时
  调试模式开关置灰（`disabled`）并 tooltip 说明「需先开启记录执行日志」。

### 1.6 表单状态与回显（调试模式）

- 新增 `const logDebug = ref(false)`；
- 编辑态：`logDebug.value = props.workflowDetail.log_debug ?? false`
  （后端三态 `boolean | null`，`null`=未设置，前端一律按「关」展示）；
- 新建态：`logDebug.value = false`。

### 1.7 保存载荷（依赖 SDK 类型）

`handleSave` 的 body（`WorkflowSaveBody`）create / update 两条链路都携带
`log_debug: logDebug.value`（与 `log_enabled` 同款布尔语义）。

> `log_debug` 需要 SDK 重新生成后才能写入 body（`WorkflowCreateRequest` /
> `WorkflowUpdateRequest` / `WorkflowDetailResponse` 新字段）——按项目 SDK 规范，
> 后端 OpenAPI 变更后由使用者手动执行重新生成，前端再接入。

### 2. 表单状态与回显

- 新增 `const logEnabled = ref(false)`；
- 编辑态：`logEnabled.value = props.workflowDetail.log_enabled ?? false`
  （后端 `log_enabled` 为三态 `boolean | null`，`null`=未设置，前端一律按「关」展示）；
- 新建态：`logEnabled.value = false`。

### 3. 保存载荷（依赖 SDK 类型）

`handleSave` 的 body 使用本地类型 `WorkflowSaveBody`
（= `Omit<WorkflowCreateRequest, 'custom_action_id'> & { custom_action_id?: string | null }`），
create / update 两条链路都携带 `log_enabled: logEnabled.value`；弹窗 `workflowDetail` prop
与列表页 `editDialogDetail` 均改用 SDK 的 `WorkflowDetailResponse` 类型。

> `custom_action_id` 按字符串透传，并在调用处做带注释的 `as unknown as` 转换：
> 雪花 ID 是 19 位整数，超出 JS Number 安全整数范围（项目「_str 后缀」约定），
> 由后端 pydantic 自行转 int；若转成 `Number()` 会丢精度、指向错误动作。
> 同类处理见 `loadActionSummary` 的 `action_id` 与 `WorkflowRunLogDialog` 的 `workflow_id`。

> 弹窗开关只会提交布尔值（开=显式开启，关=显式关闭）；
> 「未设置（null，跟随动作级/项目级开关）」只能由不带该字段的 API 调用或导入 JSON 产生。

### 4. 列表卡片展示日志状态

`src/views/rpa-browser/WorkflowManagement.vue`：

- `WorkflowItem` 接口新增 `log_enabled: boolean | null`、`log_debug: boolean | null`
  （列表响应直带，无需映射）；
- 卡片调度行新增 `workflow-card__log` 标签：开（success）/ 关（info）/ 跟随（warning），
  `title` 挂优先级说明（工作流开关 > 动作开关 > 项目兜底）；
- `log_debug === true` 时在日志标签后追加 `workflow-card__log-debug` 徽标
  「调试」（warning 色），tooltip 说明「全量记录：入参/结果/变量池、成功也记、不截断」；
- 悬浮 tooltip 补一行 `执行日志: 开/关/跟随动作/项目开关（仅保留最近 7 天）`，
  调试模式开启时再补一行 `调试模式: 开（全量记录）`。

### 5. 运行记录空态说明

`src/components/rpa-browser/WorkflowRunLogDialog.vue`：展开某次运行无步骤日志时提示
「暂无步骤日志：该工作流未开启『执行日志』开关，或日志已超过 7 天保留期被自动清理」，
避免用户误以为是接口故障。

### 6. 步骤日志分页（by-execution）

**问题**：一次长循环运行的步骤日志可达数千条，`POST /action-logs/by-execution` 一次性全量返回，
既拖慢响应（单行含 error_message 等文本，累计响应体很大），渲染也会卡顿。

**后端**：

- `ActionLogByExecutionRequest` 继承 `BasePaginationReq`（`page` / `per_page`，默认 1 / 50）；
- 响应改为 `BasePaginationResp[ActionLogItemResponse]`（`page` / `per_page` / `total` / `items`），
  与 `action-logs/list` 口径完全一致；
- 查询走「先分页取 id、再按主键回表」的两步法（与 `list()` 相同）：链路表含 `result_data` 等
  JSON 大列，直接 `ORDER BY id` + 回表会触发 MySQL `1038 Out of sort memory`；
- 排序口径：`order_desc=false`（按写入顺序升序），保持「还原调用树」的语义。

**前端**（`ActionLogChainDialog.vue` / `WorkflowRunLogDialog.vue`）：
分页查询统一走**已生成 SDK** 的 `action-logs/list`（支持 `execution_id` 过滤 + `page`/`per_page`
+ `order_desc`），无需改动生成产物：

- 执行链路弹窗：底部 `el-pagination`（`total` 取接口 `total`），默认每页 50 条，
  汇总区「共 N 步」用接口总数而非当前页条数；
- 运行记录弹窗的展开行：同样按页加载步骤日志（每页 50 条），超出时在展开区内显示分页器；
  重开某行 / 刷新列表时回到第 1 页。

> `by-execution` 的响应结构变化已同步到后端；前端当前改用分页 `list` 接口，
> 不依赖新结构，**等下次统一重新生成 SDK 后**再切回 `by-execution` 亦可。

### 7. 规则遵循

- 组件全部走 Tailwind 语义化主题类，不写 `<style>`、不用 `:style`；
- 不使用 `size="small"`，统一 default/large；
- 新配置区**不新增图标**（标题纯文字），避免引入 `assets/svgs` 之外的图标资源；
- 功能元素带 BEM 语义 class（如 `workflow-log-section` / `workflow-card__log`）。

## 验收

1. 新建工作流：默认「记录执行日志」为关；打开后创建成功，详情回显为开。
2. 编辑工作流：开关正确回显 `log_enabled`，保存后再次打开仍一致。
3. 开关打开的工作流「立即运行」后，运行记录弹窗可按 `execution_id` 下钻到步骤日志；
   开关关闭的工作流运行后无步骤日志，空态给出开关/保留期提示。
4. 导出 JSON 含 `log_enabled`，导入后保留该设置。
5. 列表卡片显示日志状态标签（开/关/跟随），悬浮提示优先级口径。
6. `nuxt typecheck` 对本次改动文件无新增错误。
7. 调试模式：打开时「记录执行日志」被自动带上；关闭记录开关时调试开关置灰。
8. 调试模式开 / 关正确回显 `log_debug`，保存后再次打开仍一致；卡片出现「调试」徽标。
9. 调试模式开启的工作流运行后，步骤日志的入参 / 结果 / 变量池均有值，
   成功步骤也有记录（常规模式下变量池为空、可按需核对）。
