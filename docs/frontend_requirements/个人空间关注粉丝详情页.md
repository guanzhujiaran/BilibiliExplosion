> 状态：**已落地**（后端接口 + 前端页面均完成）；后端见 `docs/be-message-统一计划书.md` §4.1 / §4.2
> 关联：`docs/个人空间tab路由化方案.md`、`docs/frontend_requirements/个人空间主页行为记录与隐私.md`

> 本期不含：列表内关键词搜索、`order`/`order_type` 排序（另开需求）

## 1. 入口

空间头部统计栏（菜单栏上方一行）的「关注 N」「粉丝 N」**可点击**，进入关系详情页：

| 视角 | 点击「关注」 | 点击「粉丝」 |
| --- | --- | --- |
| 自己空间 | 进「我的关注」（`/app/space/:mid/relation/follow`） | 进「我的粉丝」（`/app/space/:mid/relation/fans`） |
| 他人空间 | 进「TA 的关注」（他人窗口，最多 5 页 / 最新 120 条） | 进「TA 的粉丝」（他人窗口，最多 5 页 / 最新 120 条） |
| 视角预览（访客 / 粉丝） | 走他人窗口规则 | 走他人窗口规则 |

- 统计数字为 **0 时仍可点击**（进入空列表；2026-10-09 调整，不再置灰 / 静默拦截）；
- 统计栏布局（统计在上、菜单在下）见 `docs/frontend_requirements/个人空间主页行为记录与隐私.md`。
- **他人主页的关注按钮**（2026-10-09）：已关注时按钮变为下拉菜单「设置分组 / 取消关注」（对齐 B 站），
  「设置分组」打开 `SpaceFollowTagPicker`（支持内联新建分组）；未关注时为普通「关注」按钮。
  预览模式下拦截并提示，不做真实修改。

## 2. 页面结构（复用现有布局与组件，不新增样式体系）

```
/app/space/:mid/relation/followings   或/app/space/:mid/relation/fans   （两个固定路由，无 kind 参数）
├─ 头部：与空间页一致的头部（横幅 + 头像 + 昵称 + 统计栏，关注/粉丝数字可点）
└─ 内容：左侧「关注分组」栏（仅本人视角的关注列表）+ 右侧列表
```

> 个人资料卡属主页内容，关系页**不再重复展示**（与「时间线」tab 同一口径）。

- **路由**（2026-10-09 改为一层布局壳 + 两个子路由，对标 B 站）：
  - 父级 `/app/space/:mid/relation` → `SpaceRelationLayout.vue`（左侧 menu；访问父级重定向到关注页）；
  - 子级 `relation/follow`（`MOMENT_USER_SPACE_FOLLOWINGS`）与 `relation/fans`（`MOMENT_USER_SPACE_FANS`），
    **不引入 `kind` 参数**，分流靠两条子路由 + props；
- **组件**：
  - `views/moment/SpaceRelationLayout.vue`（**布局壳**：左侧 menu =「我的关注」分组导航 +「我的粉丝」入口；
    分组状态 `activeTagId` / `activeTagName` 由布局壳持有，经 provide/inject 下发给子页面，切子路由不丢）；
  - `views/moment/tabs/SpaceRelationTab.vue`（右栏内容：大标题 + 列表，props `relationType`）；
  - `components/moment/SpaceRelationList.vue`（列表 + 分页 + 关系操作）；
  - `components/moment/SpaceFollowTagNav.vue`（分组导航：切换 / 新建 / 删除，含「显示剩余 N 个」折叠）；
  - `components/moment/SpaceFollowTagPicker.vue`（「设置分组」弹窗，含内联新建）；
- **列表容器**：必须用 `LoadingMoreContainer`（内部 `BiliScrollbar`，项目规范第 4 条），
  不要再手写「加载更多」按钮；`show-end-text` 关闭（B 站是分页器不是「到底了喵~」文案）；
- **分页**：接口按 `pn` / `ps`（默认 `ps=24`），触底加载下一页，与 `SpaceTimelineList` 完整模式同构；
- **行内容**：头像（`el-avatar`）+ 昵称 + 「互相关注」标记；右侧按钮仅在**本人视角**出现
  （关注列表 = 「已关注」= 取关；粉丝列表 = 「回关」/「互相关注」= 取关）；
  本人视角的关注行另有「设置分组」打开分组弹窗。他人视角整行只读（关系态未知，不做猜测）。

### 2.1 布局（2026-10-09 对齐 B 站关系页）

| 区域 | 做法 |
| --- | --- |
| 左侧 menu（布局壳） | 两个区块：「我的关注」与「我的粉丝」。**本人视角**：「我的关注」恒为完整分组导航（新建分组 → 全部关注 → 特别关注 → 默认分组 → 自建分组；**粉丝页也照常展示**，点分组即切回关注列表）；**他人视角**：只有「全部关注」「全部粉丝」两个入口（分组是私域数据）。入口选中态 = **左侧主色竖条 + 浅色底 + 主色文字**；分组多于 5 个折叠为「显示剩余 N 个」；计数取自空间资料 `follow_stat`（零额外请求） |
| 右栏标题 | 大标题跟随左栏选中项（本人关注页：默认「全部关注」，选中分组后显示分组名）；粉丝页固定「全部粉丝」；他人视角「TA 的关注 / TA 的粉丝」 |
| 列表 | **多列网格卡片**（`grid-cols-1 / sm:2 / lg:3`，列间距 24px、行间距 20px），每项 = 56px 圆头像 + 昵称（主色、可点进空间）+ 关系态（互相关注）+ 本人视角的操作按钮（已关注 / 回关 / 设置分组）；卡片无边框、无底色（对标 B 站） |
| 不做 | 筛选（最近关注 / 最常访问）与关键词搜索 —— 后端暂无对应参数（见 §5 遗留），不放假交互 |

- 上述取代 §2 里「行式列表 + 卡片底色」的旧描述；分页与可见性窗口规则不变。

## 3. 可见性窗口（与后端约定）

| 项 | 值 |
| --- | --- |
| 前端最多渲染页数 | **5 页**（默认 `ps=24` → 120 条） |
| 自己视角 | 不限，可一直触底 |
| 他人视角（含预览态） | 只渲染前 5 页；第 6 页起不再请求 |
| 后端超出窗口行为 | `code=0` + `items=[]` + `total` 为真实总数（**不是错误**） |

- 前端用 `total` 计算总页数并夹住：`maxPage = isOwnView ? Infinity : 5`；
- 触底时若已达 `maxPage`，不再发请求，展示一行「仅展示最新 120 条」提示（`show-end-text` 之外的自定义行）；
- **不能**用 `total` 直接算 `el-pagination` 总页数给他人视角，必须夹到 5。

## 4. 数据来源

| 用途 | 接口（对标 B 站 `x/relation/*`） |
| --- | --- |
| 关注列表 | `GET /api/v1/message/follow/followings?vmid={mid}&pn=&ps=` |
| 粉丝列表 | `GET /api/v1/message/follow/fans?vmid={mid}&pn=&ps=` |
| 我的分组列表 | `GET /api/v1/message/follow/tags`（仅自己视角渲染） |
| 新建分组 | `POST /api/v1/message/follow/tags` `{ name, tip? }` |
| 删除分组 | `DELETE /api/v1/message/follow/tags/{tag_id}` |
| 给用户分组 | `POST /api/v1/message/follow/tags/assign` `{ target_mid, tag_ids[] }`（覆盖式） |
| 按分组过滤关注列表 | `GET /api/v1/message/follow/followings?tagid=`（`-10` 特别关注 / `0` 默认分组 / `>0` 自建） |

- query 用 **B 站命名**：`vmid`（被查看者，缺省=自己）/ `pn`（页码）/ `ps`（每页，默认 24）；
  访问者身份由网关注入的 `x-bili-mid` 决定，前端**不传** viewer；
  `order` / `order_type`（B 站的「最近关注 / 最常访问」）本期不做，下轮补；
- 响应沿用 `FollowListResp`：`items[{mid, created_at, mutual, user}] / total / page_num / page_size`；
- `user` 是 **`FollowUserBrief`**（2026-10-09 换用新模型）：只含卡片渲染需要的
  `mid / name / face / sign / level / vip_status / vip_type`；不再复用 `UserBriefOut`
  （后者带铭牌 / 官标 / 关注数等列表用不到的字段，且含私域字段）；
- 装配仍走 `PptrUser.get_many` 一次批量回查（无 N+1），由 `FollowUserBrief.from_brief()` 裁剪；
  注销 / 回查失败为 `null`，前端降级渲染「账号已注销」；
- 封装层（`src/api/notify/moment-api.ts`）：`fetchFollowings` / `fetchFans` / `fetchFollowTags` /
  `createFollowTag` / `deleteFollowTag` / `fetchAssignedFollowTags` / `assignFollowTags`
  （底层走 `services/MessageFollowService.gen.ts` 分类 Service）；
- **可见性门控**：`vmid` 为他人时，后端按主人开关 `show_follow_list` / `show_fans_list` 整类拦截
  （关闭 → 空列表且 `total=0`），与主页粉丝模块同一开关口径。
