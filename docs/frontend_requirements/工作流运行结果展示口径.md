# 工作流运行结果展示口径 · 前端需求

> 后端口径见本节 §2；本文件同时约束前端各展示点，避免同一运行在不同页面出现
> 「成功 / 失败」与计数两套说法。

## 1. 背景

运行结论原本由资源失败 / 步骤失败 / 循环中断共同决定，界面上会出现：

- 卡片：「上次运行：成功」；
- 运行记录：「状态：失败」，但「步骤 18 / 0 / 18」全绿；
- 结束 Toast / 通知：「运行失败：……」；

用户真正关心的是**这次跑了多少**，而不是后端给出的成败标签。因此运行结果统一改为
可数结果，不再展示成功 / 失败结论。

## 2. 展示规则（唯一口径）

| 条件 | 文案 |
|---|---|
| `resource_total > 0`（批量循环工作流） | `成功循环 N 轮`，N = `resource_success` |
| `resource_total = 0` 且 `total > 0` | `成功 N 步`；`N < total` 时 `成功 N/total 步` |
| 没有计数快照（迁移前的历史运行） | `-` |

- 过程状态照旧展示：`运行中` / `排队中` / `已中断` / `已停止`，这些是状态而不是成败结论；
- 标签配色只区分「进行中」与「已结束」，不再用绿色表示成功、红色表示失败；
- 运行消息面板的「运行结束」行同样只给可数结果；
- 进度条不再按 `success / failed` 着色，步骤计数改为「已完成 x/y 步」；
- `last_run_status` 仍保留在接口与数据库里，供「继续运行」按钮、运行中判定等内部逻辑使用，
  只是不再作为文案直接展示。

## 3. 界面落点

| 位置 | 文件 | 行为 |
|---|---|---|
| 工作流卡片「上次运行」 | `src/components/rpa-browser/WorkflowCard.vue` | 标签文案改为可数结果 |
| 运行记录弹窗「结果」列 | `src/components/rpa-browser/WorkflowRunLogDialog.vue` | 状态列改名「结果」，终态给计数；运行中/中断/停止仍给状态词 |
| 运行结束 Toast | `src/views/rpa-browser/WorkflowManagement.vue` | 去掉「运行成功 / 运行失败」，只报计数；失败原因附在后面 |
| 运行消息「运行结束」行 | `src/utils/rpa/workflowRunMessageFormat.ts` | 解析为计数文案 + 独立错误块 |
| 关联工作流（浏览器详情） | `src/views/rpa-browser/BrowserDetail.vue` | 同卡片口径 |
| 编辑弹窗「上次运行」 | `src/components/rpa-browser/WorkflowEditDialog.vue` | 同卡片口径 |
| 管理端列表 / 运行记录 | `src/views/rpa-browser/admin/WorkflowAdmin.vue` | 同口径 |
| 进度条 | `src/components/rpa-browser/WorkflowRunProgressBar.vue` | 去掉成功/失败计数与红绿结论色 |

统一实现位于 `src/utils/rpa/runDisplay.ts`：`runResultText` / `runStatusText` /
`runStatusTagType`，各页面不得自行拼文案。

## 4. 数据来源

| 字段 | 来源 |
|---|---|
| `success_count` / `total` | 运行记录（`WorkflowRunLogItemResponse`） |
| `resource_total` / `resource_success` | 运行记录；SSE 终态帧新增同名字段 |
| `last_run_success_count` / `last_run_total` / `last_run_resource_*` | 工作流表的上次运行快照（终态事件写入） |

- 工作流列表 / 详情响应新增 4 个 `last_run_*` 字段，卡片无需再查运行记录；
- SSE 进度帧新增资源四元组（`resource_total / resource_success / resource_failed / resource_skipped`），
  结束 Toast 直接用终态帧里的计数；
- 生成的 hey-api SDK 尚未包含新增的 `last_run_*` 字段：前端先用本地类型补齐
  （`WorkflowItem` / `AdminWorkflowItem` / `WorkflowEditDialog` 的本地字段声明），
  **不修改生成产物**，下次生成 SDK 后自动对齐。

## 5. 验收

1. 有资源记录的工作流跑完后：卡片、运行记录、Toast 均显示「成功循环 N 轮」；
2. 纯步骤工作流跑完后：三处均显示「成功 N 步」（未跑满为「成功 N/M 步」）；
3. 运行中 / 中断 / 停止仍显示状态词，且中断行仍可「继续」；
4. 历史运行（4 个快照字段均为 0）：卡片显示 `-`，不显示「成功 0 步」；
5. 站内 / 站外通知标题为「工作流执行完成」，正文只有「处理结果 / 执行步骤」计数与错误详情；
6. 运行消息面板的结束行显示计数，不再出现 `success/failed` 英文枚举。
