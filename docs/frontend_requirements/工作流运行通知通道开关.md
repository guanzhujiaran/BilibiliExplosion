# 工作流运行通知：站内 / 站外 × 开始 / 结束 四象限勾选（WorkflowEditDialog）

## 背景

「运行通知」区原先是两个**通道混合**的开关（`notify_on_start` / `notify_on_end`）：打开后站内系统通知
与站外推送（PushMe / PushPlus / webhook 等）同时发，用户无法只留站内留档、只推手机，也无法
「开始只收站内、结束再推手机」。

后端已按 `docs/RPA-Browser` 的《通知动作与运行告警计划书》§E 拆成 2×2 矩阵：

| | 开始（`start`） | 结束（成功 / 失败 / 停止） |
|---|---|---|
| 站内（`inbox`） | `notify_inbox_on_start`（默认 false） | `notify_inbox_on_end`（默认 true） |
| 站外（`push`） | `notify_push_on_start`（默认 false） | `notify_push_on_end`（默认 true） |

旧字段 `notify_on_start` / `notify_on_end` 仍被后端接受（按双通道展开），但前端不再提交。

## 前端需求

### 1. 位置与容器

`src/components/rpa-browser/WorkflowEditDialog.vue` 的「运行通知」区（现有
`workflow-notify-section`，位于「触发 / 浏览器」区之后、「断点恢复」区之前）。

保留现有边框卡片容器与标题行（`Bell` 图标 + 「运行通知」+ 一行说明），把标题右侧说明改为：

> 站内通知进消息中心；站外推送需先在「推送设置」中配置渠道，未配置时站外勾选不生效。

### 2. 2×2 勾选矩阵

形状：两行两列，第一行是表头（行标签列 + 「开始」「结束」两个列头），第一列为通道标签。

| | 开始 | 结束 |
|---|---|---|
| 站内通知 | ☐ | ☑ |
| 站外推送 | ☐ | ☑ |

- 每个单元格一个 `el-checkbox`（default 尺寸，禁止 `size="small"`），标签文字直接用列头语义，
  单元格内不再重复「站内 / 站外」字样；
- 行标签：`站内通知`（附小字 `消息中心`）、`站外推送`（附小字 `PushMe 等`）；
- 列头：`开始`、`结束`（结束列头加小字 `成功 / 失败 / 停止`）；
- 使用 CSS Grid（`grid grid-cols-[auto_1fr_1fr]` 一类 Tailwind 原子类）对齐，禁止 `<style>` 与 `:style`；
- 结构与语义 class：
  - 容器 `workflow-notify-matrix`
  - 行 `workflow-notify-matrix__row`（含 `--head`）
  - 单元格 `workflow-notify-matrix__cell`
  - 单个勾选 `workflow-notify-matrix__check` + `id`（如 `workflow-notify-inbox-start`）
    —— 便于自动化脚本精确定位；
- 行内说明（弱化文字，`text-xs text-color-secondary`）：
  - 站内行：「无需配置，仅受账号「接收系统通知」开关约束」；
  - 站外行：「需先在推送设置中配置渠道；免打扰时段由消息服务端统一拦截」。

### 3. 表单状态

新增 4 个 `ref`（替代原 `notifyOnStart` / `notifyOnEnd`）：

```ts
const notifyInboxOnStart = ref(false)
const notifyInboxOnEnd = ref(true)
const notifyPushOnStart = ref(false)
const notifyPushOnEnd = ref(true)
```

- 编辑态：取详情对应的 4 个字段，缺省回落上述默认值（`?? false` / `?? true`）；
  详情里若只有旧的 `notify_on_start` / `notify_on_end`（存量数据尚未迁移），
  按双通道展开回显：`inbox = push = notify_on_start`、`inbox = push = notify_on_end`；
- 新建态：站内-开始关 / 站内-结束开 / 站外-开始关 / 站外-结束开。

### 4. 保存载荷

`handleSave` 的 body 携带 4 个布尔字段，**不再提交** `notify_on_start` / `notify_on_end`：

```ts
notify_inbox_on_start: notifyInboxOnStart.value,
notify_inbox_on_end: notifyInboxOnEnd.value,
notify_push_on_start: notifyPushOnStart.value,
notify_push_on_end: notifyPushOnEnd.value,
```

`WorkflowSaveBody` 仍沿用 `Omit<WorkflowCreateRequest, 'custom_action_id'> & { custom_action_id?: string | null }`，
4 个字段直接来自 SDK 类型，**不新增本地扩展类型**。

### 5. 类型与 SDK

后端 4 个字段已进入 OpenAPI，SDK 已重新生成并收录（`types.gen.ts` 的
`WorkflowCreateRequest` / `WorkflowUpdateRequest` / `WorkflowDetailResponse` /
列表项均带 `notify_inbox_on_*` / `notify_push_on_*`）。

- 组件不再声明本地扩展类型（早期草稿里的 `WorkflowNotifyMatrixFields` /
  `WorkflowDetailWithNotify` 已在 SDK 更新后删除）；
- 详情回显直接读 `props.workflowDetail.notify_inbox_on_*`，缺失时（老数据）按旧字段
  `notify_on_start` / `notify_on_end` 双通道展开。

### 6. 规则遵循

- 全部 Tailwind 语义化主题类，不写 `<style>`、不用 `:style`；
- 不使用 `size="small"`，`el-checkbox` / `el-switch` 统一 default；
- 不新增图标（标题沿用现有 `Bell`），不引入 `assets/svgs` 之外的资源；
- 功能元素带 BEM 语义 class 与 `id`。

## 验收

1. 新建工作流：矩阵默认「站内-开始 关 / 站内-结束 开 / 站外-开始 关 / 站外-结束 开」；
2. 编辑工作流：4 个勾选正确回显；保存后重新打开仍一致；
3. 只勾「站内-结束」：运行结束只产生站内消息，不触发站外推送；
4. 只勾「站外-结束」且未配置推送渠道：不发站内消息，日志有「未配置外部推送，跳过」；
5. 只勾「站内-开始」：运行开始有站内消息，结束时无任何通知；
6. 导出 JSON 含 4 个新字段；导入后矩阵回显一致；
7. `nuxt typecheck` 对本次改动文件无新增错误。
