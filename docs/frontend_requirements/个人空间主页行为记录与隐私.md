## 0.2 时间线条目卡片化（2026-10-07 定稿，方案 A）

**背景**：时间线原实现是「一行式文本 + 摘要截断」，且后端 `SpaceTimelineService` 对
`TResourceLike` / `TResourceFavorite` 写死 `bizType == DYNAMIC` 过滤，出参也只有
`target_text` / `target_dyn_id`，**前端既判断不了资源类型，也拿不到动态的完整内容**
（无法复用 `MomentCard`）。

**定稿：条目两层结构**

| 层 | 内容 | 组件 |
| --- | --- | --- |
| 外层 | 「谁」+「做了什么」+ 时间：头像、昵称、`点赞了 / 收藏到收藏夹「X」` | 条目自身（`SpaceTimelineList` 内渲染） |
| 内层 | **资源卡**：dynamic → 完整动态卡；非 dynamic → 与动态详情里一致的附加资源卡 | `MomentCard` / `MomentAttachCard` |

**后端改造（不改表）**

1. `SpaceTimelineItem` 新增 `target_resource: SpaceTimelineResource | None`：
   - `biz_type: str`（`dynamic` / `lottery` / `rpa_*` / …，即 `InteractionBizTypeEnum.to_text()`）
   - `biz_id: int`（`@auto_str` 自动派生 `biz_id_str`，19 位雪花 id 前端必须用字符串）
   - `name` / `cover` / `jump_url`（非 dynamic 资源实时回查，弱依赖降级为 `None`）
   - `moment: MomentDetailResp | None`（dynamic 时内联完整动态，前端直接喂 `MomentCard`）
2. `SpaceTimelineService.list` 放开资源类型：
   - 点赞 / 收藏查询把 `bizType == DYNAMIC` 从 `WHERE` 移到 `LEFT JOIN ... ON` 条件，
     仅当资源是 dynamic 时才要求 `TMoment` 未删除且审核 normal；非 dynamic 条目照样返回；
   - dynamic 条目用现成 `MomentFeedService.get_details_batch`（限 20 条，与页大小一致）批量内联，
     **不产生 N+1**；
   - 非 dynamic：`lottery` 走既有 lottery RPC 批量回查 `name/cover/jumpUrl`；
     RPA 类复用 `RpaRpcClient.get_resource_detail`（弱依赖，失败降级 `None`）。
3. **前端 SDK 必须重新生成**（出参契约变更），按仓库规则停在「后端就绪 + 封装层草稿」，
   由用户手动执行 `npx @hey-api/openapi-ts`；前端组件用本地类型断言读取新字段并标注 TODO。

## 3. 后端改造清单

### 3.1 空间展示「上次登录 + 属地」（加查询，**不改表**）

- 数据源：pptr `TUserActInfoLog`（`be-message-service/app/models/pptr_db.py:164-190`）
  字段：`pk / mid(FK→TUserInfo.uid) / ip VARCHAR(50) / ua / headers JSON / act_info / createdAt / deletedAt`
  `act_info` 取值：`daily_login`（`base.py:404-425`）、`login_succ`（`casdoor_service.py:704-711`）、`reg`（`:681-689`）
- 写入点已有**天然节流**：`get_user_nav_data` 只在 `add_daily_login_exp()` 返回 `can_add_exp` 时写一条，
  即**每天首次登录才一条**（`base.py:408-425`）→ 语义正好就是「最后一次登录」，不需要自己加节流
- **需要新增**：一个「按 mid 取最近一次登录记录」的服务方法，供 `/user/space/info`（查他人）与
  `/user/space/info`（查自己）复用。实现照抄 `list_act_log` 的查询 + `geo_lookup` + `_mask_ip`：
  ```python
  # 伪代码要点
  stmt = (
      select(PptrUserActInfoLog)
      .where(
          col(PptrUserActInfoLog.mid) == target_mid,
          col(PptrUserActInfoLog.deletedAt).is_(None),
          col(PptrUserActInfoLog.act_info).in_(("login_succ", "daily_login")),
      )
      .order_by(col(PptrUserActInfoLog.createdAt).desc())
      .limit(1)
  )
  ```
  出参 pydantic 放 `app/models/schemas/space.py`：`last_login_at: datetime | None` + `ip_location: str | None`
  （属地已经过隐私开关过滤；IP 本身**不需要**返回给空间页。字段口径见 §5，只展示到日期粒度）
- **需要一条索引 DDL**：`TUserActInfoLog` 目前**只有主键和外键，没有 mid/createdAt 索引**
  （`pptr_db.py:166-170`；建表迁移 `be-gateway/ExpressServerEnd/migrations/20240101000023-create-TUserActInfoLog.js:5-15`
  也没 `addIndex`），按 mid 取最新一条会全表扫。对比同库的 `TUserExpRecord` 有
  `idx_exp_record_mid_action_ref_date`（`pptr_db.py:201-202`）。
  pptr 库有独立迁移目录 `be-message-service/alembic_pptr/versions/`（参考
  `20260810_1031-d366ed68066f_sync_models_to_production.py:35`），走那里加一条即可。
  顺带这条索引对已有的 `list_act_log`（`base.py:1135-1145`，同样按 mid + createdAt 查、同样全表扫）也是收益

### 3.2 资料字段隐私（改表 + 改接口）

- 现状**没有**字段级隐私表，全库只有 `TUserFavoriteSetting.showFavorites`
  （`be-message-service/app/services/interaction_actions/folder.py:389-423`）
- `SpaceInfoResp` 字段来源（`be-message-service/app/services/user/account/base.py:357-402`）：

  - `email` ← pptr `TUserDetail.email` 存在，但 `SpaceInfoResp` **不返回** → 需加字段
  - `ipLocation` + `lastLoginAt` ← §3.1 新增
- 新增模型（**默认全部不展示**，主人显式开启才对外可见；三组开关对应设置页三个区块）：

```python
# be-message-service/app/models/db/space_privacy_tbl.py
class TUserSpacePrivacy(TimestampMixin, table=True):
    """空间对外可见性（每用户一行，get_or_create 懒创建，默认全关）。

    `viewer == mid` 时一律不过滤。
    """

    __tablename__ = "TUserSpacePrivacy"
    __table_args__ = (
        PrimaryKeyConstraint("mid", name="TUserSpacePrivacy_pkey"),
        {"extend_existing": True, "comment": "空间对外可见性：每用户一行，默认全关"},
    )

    # DB 层 mid 用 BIGINT int（对齐 msg_user_setting.mid / TUserFavoriteSetting.mid 的既有约定）；
    # 前端传 str 由 pydantic 层的 StrInt 包装转换，不在 DB 层做 str
    mid: int = Field(
        default=None,
        primary_key=True,
        sa_type=BIGINT,
        sa_column_kwargs={"autoincrement": False},
        description="用户mid",
    )

    # ---- 基本信息（敏感原文，关闭时后端直接不下发字段）----
    show_personal_info: bool = Field(
        default=False, description="个人资料：性别/生日/邮箱是否对外"
    )
    # 注：上次登录时间 / IP 属地**不设开关**，固定公开（2026-10-08 调整，见 §0.1.1）

    # ---- 行为记录（TA 主页时间线条目按类型过滤）----
    show_follow_list: bool = Field(
        default=False, description="时间线里「我关注了谁」条目是否对外可见"
    )
    show_like_list: bool = Field(
        default=False, description="时间线里「我点赞了什么」条目是否对外可见"
    )
    show_fans_list: bool = Field(default=False, description="我的粉丝列表是否对外可见")
```

**故意不设开关的项**（避免无用列 / 无作用对象）：

| 项 | 理由 |
| --- | --- |
| 统计数字（关注数 / 粉丝数 / 获赞 / 动态 / 被访问次数） | 已定稿**保持显示、不受开关控制**；且它们不在主页 tab 内（渲染在头部统计栏），不受「开关只作用于主页」原则约束 |
| **上次登录时间与 IP 属地** | **2026-10-08 定稿：不设开关、固定公开**（原计划的 `show_login_info` 已废弃，见 §0.1.1）：属账号安全提示类信息，B 站也固定展示 |
| 收藏夹对外展示 | **2026-10-08 改版**：改为收藏夹逐个 `TFavoriteFolder.is_public`，不再有全局 `showFavorites`（见 §0.1.2） |
| 最近动态摘要 | 已定稿固定展示；且 feed 已按 `auditStatus` 过滤，可见即已过审 |
| 签名 / 等级 / 头像 | 空间核心展示，全关就没有内容；B 站也不提供这三个的开关 |
| 主页模块排序（`index_order`） | 本期不做；真要做时另加一张排序表或 JSON 列（不用 dict 表达模块定义） |

- **过滤语义**：`viewer != mid` 且开关关闭时
  - **敏感原文**（`email` / `sex` / `birthday`）→ **后端不下发字段**（不是 null），前端不用猜「null 是没权限还是没数据」
  - **时间线条目** → 该类型条目**不出现在结果里**（不是返回空对象）
  - **粉丝列表** → 复用 `show_fans_list`，关闭时模块整块不返回；**收藏夹** → 逐夹 `is_public` 过滤（见 §0.1.2）

### 3.3.1 时间线语义：**当前有效状态**，不是操作流水（2.58.0 定稿）

**用户要求**：取消点赞后，时间线里不能再出现这条点赞记录；所有资源都按这个口径。
即时间线反映的是「现在还成立的关系 / 行为」，**不是「曾经做过什么」的操作日志**。

好在四类「取消」在数据层全部是**物理删除**，所以「行存在即有效」这条天然成立，
**不要**去加 `deletedAt` / `status` 过滤（这些列在赞 / 踩 / 收藏表里根本不存在）：

| 行为 | 取消的落库方式 | 时间线「当前有效」的 WHERE 条件 |
| --- | --- | --- |
| 点赞 `TResourceLike` | 物理 DELETE（`ops.py:98` / `ops.py:162`） | 行存在即有效（唯一键 `(bizType,bizId,mid)` 保证 ≤1 行） |
| 点踩 `TResourceDislike` | 物理 DELETE（`ops.py:211`、`dynamic/biz.py:178`） | **不进时间线**（负面行为，B 站也不展示） |
| 收藏 `TResourceFavorite` | 物理 DELETE（`ops.py:325`、`dynamic/biz.py:244`）；删夹级联删明细（`folder.py:264`） | 行存在即有效 |
| 关注 `msg_user_follow` | 取关物理 DELETE（`follow.py:96`） | **必须**加 `status = 'FOLLOWING'`（=1） |

**两个必须显式处理的陷阱（否则时间线会出错）**：

1. **`msg_user_follow` 必须过滤 `status`**：拉黑是把同一行**原地翻转**成 `BLOCKED`（`follow.py:132-146`，
   且保留原 `created_at`），所以只看 `mid/target_mid` 会把「被拉黑的人」当成「已关注的人」展示出来。
   现成 `list_following` 已经这么过滤（`follow.py:294`），照抄即可。
2. **动态被删后，赞 / 收藏行不会级联删除** —— 动态软删只置 `TMoment.deletedAt`（`moment_publish.py:721`），
   `TResourceLike` / `TResourceFavorite` 里会残留**指向已删动态的行**（`cleanup_moment.py:70-87`
   只在账号注销时才清理）。因此时间线必须 JOIN 目标资源校验可见性：
   ```sql
   JOIN TMoment ON TMoment.dynId = TResourceLike.bizId
    AND TMoment.deletedAt IS NULL
    AND TMoment.auditStatus = 'NORMAL'
   ```
   口径直接复用现成的「对外可见动态」条件（`moment_feed.py:1257-1258` / `interaction_status.py:109-114`）。

**收藏条目要去重**：`TResourceFavorite` 的唯一键是 `(bizType,bizId,folderId)` 而不是 `(…,mid)`，
同一资源可以进多个夹 → 时间线必须**按 `(bizType,bizId)` 去重**，否则一条动态刷出 N 条收藏记录。

**范围收敛**：只有 `bizType=DYNAMIC` 能在本地 JOIN `TMoment` 校验；lottery / others_lot_dyn / rpa_*
本地无主表，需要按 bizType 分支或 RPC 降级（`interaction_status.py:117-130`）。
因此本期时间线**只聚合 dynamic + 关注**，其他 bizType 不进（等有统一存在性校验方案再扩）。

**可复用的索引**（时间线按 `mid + created_at DESC` 排序直接命中）：
`idx_resource_like_mid_time`（`resource_tbl.py:45`）、`idx_resource_favorite_mid_created`（`favorite_tbl.py:70`）、
`idx_follow_mid_status(mid, status, created_at)`（`follow_tbl.py:42`）。

### 3.4 浏览历史（加接口，不改表）

- `TInteractionViewLog` 唯一键 `(bizType,bizId,mid)`，只有 `viewCount` + `lastViewAt`，
  **同一资源多次访问会合并成一条**（`be-message-service/app/models/db/interaction_tbl.py:28-39`）。
  本期按这个精度做；要做逐条流水才需新表 `TUserViewHistory`

## 5. 时间字段定稿：「上次登录时间」，不做「上次活跃 / 在线」

**结论：空间页只展示「上次登录时间 + 属地」，合并成一个展示块、**固定公开（不设隐私开关）**
（2026-10-08 调整，见 §0.1.1）。不展示「上次活跃」「在线状态」。**

| 口径 | 数据源 | 结论 |
| --- | --- | --- |
| 上次活跃 / 在线 | `msg_user_activity.last_active_at` | **弃用，语义不对**。心跳 `useHeartbeat` 只在消息中心布局启动（`src/composables/useHeartbeat.ts:19-59`，60s 一次，唯一调用方 `src/views/message/MessageLayout.vue:95`）。用户不逛消息中心就长期不更新 → 展示的其实是「上次打开消息中心的时间」；纯浏览（看动态、看空间）完全不刷新 |
| **上次登录** | pptr `TUserActInfoLog.createdAt` | **采用**。语义准确，且零额外成本：§3.1 取属地时顺手就拿到了 |

**字段口径**：
- 后端出参 `lastLoginAt: datetime | None`（ISO 字符串），**不在后端做格式化**——
  「3 天前」还是「2026-10-01」由前端决定（复用抽出来的公共 `formatRelativeTime`）
- 展示粒度默认**只到日期**：当天/昨天/N 天前 → 超过 30 天显示 `YYYY-MM-DD`。
  既保护隐私（不暴露精确作息），也够用
- 无记录（从未登录 / 数据被清理）→ 展示「暂无记录」，不渲染占位

若以后要做真实「活跃/在线」，前置条件（按成本排序）：
1. 先把心跳提到全站（App.vue 级）或改成请求驱动 —— 后端已有若干请求驱动写入点
   （`app/api/notify.py:62,113`、`app/api/event.py:67`、`app/api/dm.py:116`），
   但**纯 GET 浏览路径不写活跃**，这是当前最大的缺口
2. 再加「按他人 mid 查活跃」的接口（现在只有自身的 `GET /message/setting/activity` 与
   `POST /message/msg_feed/heartbeat`，见 `app/api/setting.py:49-58`、`app/api/msg_feed.py:48-62`）
3. 隐私上要慎重：暴露在线状态等于暴露作息（B 站是等级门槛才显示互关在线），届时应纳入隐私开关

**实现调整（与原设计的差异）**

1. **数据总览不在主页重复**：`follow_stat` / `upstat` 已在布局壳头部展示同一份数据，
   主页再放一份会让用户以为是两套数据 → 我的主页不放总览，TA 主页同理
2. **TA 主页不重复头部已有字段**：昵称 / 头像 / 等级 / 签名 / 关注私信按钮都在头部，
   主页只放头部没有的东西（动态摘要、收藏概览）；生日 / 性别 / 邮箱 / IP 属地等
   按 §0 决策「默认不展示」，要等 P1 隐私开关落地后才展示，所以先占位
3. **新增 `authReady` 门控（重要）**：`isOwnSpace` 依赖异步就绪的 `user_nav.uid`，
   自身空间（`/app/space/{uid}`）在 uid 到齐前会被误判为他人空间 → 主页在两个组件间跳变。
   现在只有 `/app/space`（无 mid，归属未知）等 uid；`/app/space/:mid` 直接放行
   （uid 为空只说明未登录，此时一定不是自己），避免未登录访客卡在 loading
4. **分流用组件映射，不拆 URL**：URL 仍是 `/app/space/:mid`（分享链接两种视角都自洽）
5. 登录记录时间用 `formatDateTime`（绝对时间）而非相对时间：相对文案在 SSR / CSR
   两端可能算出不同结果（hydration mismatch），登录记录场景也不需要「刚刚」

**验证**：`vue-tsc` 本次文件 0 错误；`check:route-root` 通过；dev server 实测
`/app/space/1` 渲染 TA 的主页、`/app/space/1/dynamic` 渲染动态 tab、`/app/space` 未登录不卡 loading。

**关键实现决策**

1. **`mid` 用 BIGINT int**（对齐 `msg_user_setting` / `TUserFavoriteSetting` 既有约定），
   前端传 str 由接口层 `StrInt` 转换，**不在 DB 层做字符串存储**
2. **敏感字段「不下发」而非下发 null**：路由已有 `response_model_exclude_none=True`，
   关闭时置None 即从响应里消失，前端不用猜 null 的含义
3. **属地不入库**：读取时 `geo_lookup(raw_ip)` 实时解析。额外处理：`geo_ip` 对无法解析的
   IP 返回「未知」，直接透传会让空间页显示负信息，因此把它**视为无数据**返回 `None`
4. **空间浏览上报零后端改动**：`InteractionBizTypeEnum.USER` 已登记 `UserBiz` 资源类
   （`check_exists` 走 pptr 校验用户存在），前端进入他人空间时调一次
   `GET /community/interaction/status/{mid}?bizType=user` 即可 +1
   （单资源接口才计数，批量接口不计；后端已按每用户每资源每自然日去重）
5. **默认口径与收藏夹相反**：隐私表默认全关（避免新账号泄露邮箱 / 属地），
   `showFavorites` 缺省仍为展示（既有行为不变）
