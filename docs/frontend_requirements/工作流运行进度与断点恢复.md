# 工作流运行进度（SSE）与断点恢复 · 前端需求

> 后端契约见 `docs/rpa-workflow-调度外壳计划书.md` §10。本文件只描述界面行为。

## 1. 数据来源

| 用途 | 接口 |
| --- | --- |
| 运行进度（实时） | `GET /api/v1/rpa/browser/control/workflows/runs/events?run_id=`，`text/event-stream`，事件名 `workflow_run_progress` |
| 运行记录列表 | `POST /workflows/runs`（含进度与恢复字段） |
| 继续运行 | `POST /workflows/runs/resume`，body `{ run_id }` |
| 工作流自动恢复开关 | 工作流 `create / update` 的 `resume_on_restart` |

进度帧字段：`status / started_at / finished_at / duration_ms / total_steps / completed_steps /
current_step_index / current_step_name / success_count / failed_count / loop_action_name /
loop_index / loop_total / loop_total_known / resume_of / resume_count / error_message`。
时间一律秒级时间戳。终态为 `success / failed / interrupted / cancelled`，收到后服务端关闭连接。

## 2. 进度条口径（核心）

双层进度，按用户关注点切换：

1. **循环体内**（`loop_total > 0` 或 `loop_index > 0`）：**两条进度条**
   - 第一条（循环总进度）：`loop_index / loop_total`，文案「第 3/20 轮 · 循环「批量点赞」」；
   - 第二条（本轮动作进度）：`loop_body_completed / loop_body_total`，文案「本轮动作 2/5 · 点击关注」，
     每轮开始时归零，动作完成时递增；`loop_body_total=0`（非循环体/未知）时不显示。
2. **不在循环内**：进度条 = `completed_steps / total_steps`，文案「步骤 2/5 · 导航到动态页」。
3. **分母未知**（条件循环 `loop_total_known=false` 或首帧未到）：不确定态动画 + 文案
   「已执行 i 轮」，**禁止伪造百分比**。

状态配色只用 Element Plus 语义 `status`（success / warning / exception），不硬编码颜色。

### 2.1 两条进度条必须分块展示（禁止并排/紧贴）

两条进度条代表两个互斥维度（整体轮次 vs 单轮内部动作），**不得上下紧贴成一组**
（曾出现两条 `el-progress` 只隔 4px，视觉上像一条被截断的进度条，用户无法分辨归属）。

展示约定：

| 项 | 约定 |
| --- | --- |
| 分组容器 | 每条进度条各自一个区块（`__group--main` / `__group--body`），纵向排列 |
| 区块标题 | 每条进度条上方一行标题，说明该条是什么：`循环总进度` / `执行进度` / `本轮动作进度` |
| 百分比 | 标题行右侧显示 `45%`（不确定态显示 `—`，不伪造数字） |
| 状态文案 | 标题行下方单独一行显示该条对应的文案（轮次/步骤名），长文本 `truncate` |
| 区隔 | 第二条与第一条之间用分隔线 + 上内边距隔开；区块间距大于区块内部间距 |
| 紧凑模式 | `compact`（表格行内）仅缩小间距与描边宽度，仍保持「标题 + 进度条 + 文案」的分块结构 |

## 3. 运行时长

本地每秒自增（基于 `started_at`），不依赖推送频率；终态改用后端 `duration_ms`。
展示 `mm:ss`（超过 1 小时为 `h:mm:ss`）。运行中显示「已运行 03:12」，结束后显示「耗时 03:12」。

## 4. 其余状态信息（尽可能完整）

- 成功/失败步骤数（运行中实时递增）；
- 当前步骤名、当前循环动作名与轮次；
- 触发来源（手动/定时）；
- 恢复次数（续跑自某运行）；
- 「进度较久未更新」提示（运行中且 60s 无新帧，说明可能在执行长耗时动作）；
- 停止中状态（点击停止后按钮 loading，等待步骤边界收口）。

## 4.5 运行消息栏（步骤级明细）

同一 SSE 连接还会推送 `workflow_run_log` 增量事件（字段见后端计划书 §10.5）：

| kind | 展示 |
| --- | --- |
| `step_started` | ▶ `开始步骤 1/16：导航` |
| `step_finished` | ✓/✗ `完成步骤 1/16：导航，耗时 1.2s`（失败带错误原因） |
| `loop_iteration` | ↻ `第 3/20 轮 · 循环「批量点赞」` |
| `loop_finished` | ⚑ `循环「批量点赞」结束（共 20 轮）`，未跑满时显示「执行 2/35 轮，提前退出」 |
| `body_step_started` | ▸ 缩进展示：`第 3 轮 · 动作 2/9：click`（循环体内动作开始） |
| `body_step_finished` | ✓/✗ 缩进展示：`第 3 轮 · 动作 2/9：click，耗时 1.2s` |
| `run_finished` | ✓/■ `运行结束：success（成功 12 / 失败 0 / 共 16 步）` |

**循环体内动作可见性**（此前 loop 内部操作完全看不到，只能看到轮次）：

后端**全量打印**——打印（SSE 消息）与落库是两件事，消息不写盘、不占硬盘，
所以不按条数或内容裁剪（成功/失败都带完整 `detail`，`workflow_run_log_detail_max_length`
默认 0 = 不限制）。消息太密属于**呈现问题**，由前端按轮次**分批收拢**：

- 以 `loop_iteration` 为分组头，其后属于本层的消息归入该分组；**嵌套循环照单全收**——
  后端每层都打印并带 `depth`（0=顶层步骤，1=最外层循环体，2=再内一层…），
  前端用分组栈把更深的循环挂到外层循环下面，形成「组里套组」的树（详见 §4.5.1）；
- 每行按所在分组的嵌套层级逐级缩进（`pl-3` + 左侧竖线，任意深度不溢出），
  视觉上就是「一层套一层」，不需要为嵌套做特殊分支；
- 分组头展示轮次徽标 + 循环名 + 状态标签 + 本组条数/失败数，**可点击折叠/展开**
  （折叠后其下所有更深层内容一起隐藏且不渲染）；
- 默认展开**最新一批及其祖先链**（正在跑的那一轮），历史批次默认折叠，
  避免 368 轮平铺刷屏；用户手动展开/折叠的分组以 `(run_id, seq)` 记录，不被自动展开覆盖；
- `detail` 仍默认折叠一行、点击展开全文；
- 前端展示窗口 1000 条（超出只保留最近的）——这只是 DOM/内存层面的窗口，
  不是后端打印的限制。

#### 4.5.1 按循环分组的树形视图（消息面板升级）

原实现是「扁平行 + `ml-*` 缩进」，轮次之间没有容器边界，消息一多就分不清「哪几条属于哪一轮」。
升级为**真正的树**：

- **数据结构**：`loop_iteration` 开一个分组节点，其后同层消息作为它的子节点；
  嵌套循环的 `loop_iteration`（`depth` 更大）挂到当前分组节点下，形成「分组里套分组」；
  `loop_finished` 不再单列一行，而是收口所属分组（置 `closed` 并记录尾部文案，展开时显示在组内底部）；
- **分组头**：轮次徽标（`第 3/40 轮`）+ 循环名 + 状态标签（运行中 / 已完成 / 提前退出）
  + 直接子项条数 + 失败数（>0 才显示，红色）+ 本轮耗时；
- **层次表达**：用嵌套容器（`pl-3` + 左侧竖线）替代固定 `ml-*` 档位，任意嵌套深度都不会溢出面板；
- **折叠即不渲染**：折叠的分组**不渲染子树**（`v-if`），1000 条消息时 DOM 也只保留展开部分，
  保证消息密集时滚动流畅；
- **默认展开**：最新一轮（及其祖先链）默认展开，历史轮次默认折叠；用户手动展开/折叠的轮次
  以 `(run_id, seq)` 记录，不被自动展开覆盖；
- **快速定位**：「轮次」下拉按执行顺序列出全部分组（嵌套用 `›` 前缀表示层级），
  选中后自动展开该轮及其祖先链并滚动到可视区顶部；
- **按轮复制**：每个分组头部一个「复制本轮」按钮，把**该轮及其所有嵌套子轮**的消息
  按时间顺序导出成纯文本（时间戳 + 级别 + 文案，失败行附 `detail` 与错误信息），
  用于贴给他人/自己定位问题；复制走 `navigator.clipboard`（失败时回落到隐藏 textarea），
  按钮点击需 `stop` 阻止冒泡，避免误触发折叠；复制成功给一次轻提示；
- **展开/收起全部**：一键展开所有分组，或收起所有分组（保留最新一轮）；
- **跟随最新**：仅在滚动条贴底时自动滚到新消息；用户上翻查看历史时**不再强制跳到底部**，
  面板右下浮动「回到最新」按钮，点击恢复跟随；
- **面板头部概览**：总消息数、失败条数（>0 标红）、当前轮次，一眼看出整体进度。

**步骤返回内容（`detail`）**：`step_finished` 事件可能带 `detail`（字符串，无内容时为 `null`），
是该步骤动作的**返回内容**（如 `fetch_external_data` 的接口响应 JSON，超长已由后端按结构裁剪并
追加 `…(已截断)`）。展示规则：

- 有 `detail` 时在 `text` 下方换行渲染，等宽字体、小号、次级文字色，`break-all` 不撑破面板；
- 默认折叠为一行（点击本条消息展开全文 / 再点收起），避免大响应刷屏；
- 复制按钮可选（本期不实现，后续按需）。

界面：**全局**悬浮入口 + 面板（`WorkflowRunMessageDock.vue`，挂在 `App.vue`，非模态浮窗）：

- **不用 `el-dialog` 承载**：`el-dialog` 自带遮罩与无条件焦点陷阱（`trapped: visible`），
  会打断用户「边跑边看边操作页面」的主流程；且它也没有内置 `resizable`（仅 `draggable`）。
  继续保持 `fixed` 浮窗，自行实现拖动与缩放。
- **可拖动**：按住面板标题栏拖动移动（`pointerdown/move/up` + `setPointerCapture`），
  标题栏内按钮 `pointerdown.stop` 不触发拖动。
- **可调整大小**：右下角把手（`cursor-se-resize`）拖动改宽高，最小 320×220，
  最大不超过视口减去 16px 边距。
- **几何持久化**：位置与尺寸写入 `localStorage`（key `workflow-run-message-dock-geometry`），
  关闭再打开保持上次摆放；窗口 `resize` 后重新 clamp 回视口内；数据损坏/不可用回落默认值。
- **复位**：标题栏提供「恢复默认位置与大小」按钮，清除存储并回到右下角默认几何。
- **几何写入方式**：组件通过 DOM `style.setProperty` 写 CSS 变量（**不使用 `:style` 绑定**），
  消费规则集中在 `src/assets/app-tailwind.css` 的 `@layer components`
  （`.workflow-run-message-bar.is-positioned`），组件内不写 `<style>` 块。


- 默认收起，右下角悬浮按钮（带未读数角标）打开；有消息或运行中才出现；
- 头部：标题 + 工作流名 + 运行中/已结束标签 + 清空 + 收起；
- 列表：时间（秒级时间戳转 `HH:mm:ss`）+ 级别图标 + 后端 `text`，新消息自动滚到底；
- 最多保留 200 条（循环体量大时只保留最近部分）；按 `(run_id, seq)` 去重；
- **SSE 订阅放在 Pinia store（`stores/workflow_run_messages.ts`）**：切换路由/页面
  不会断开，消息持续累积，未读数在面板收起时累加；
- 多个工作流并发运行时，面板跟随最近一次订阅/发起的那次运行（切换运行会清空历史）；
- 连接异常时静默回退轮询（进度仍有，消息仅 SSE 提供）。

### 6. 已处理数据（去重数据源）

接口：`POST /browser/control/workflows/resources/list`（`workflow_resource_api.ts` 薄封装）。

入口：独立页面 `/app/rpa-browser/workflows/resources`（侧边导航「自动化 → 已处理数据」）；
工作流卡片「已处理数据」按钮带 `?workflow_id=` 跳转并预选该工作流。页面展示：

- 表格列：记录ID（去重表主键）、资源类型、业务主键（`resource_id`，可复制）、
  状态（success/skipped/failed 用语义标签）、处理次数、浏览器、所属运行（run_id 前 8 位）、
  备注（`extra.reason` 优先，其次 `fail_reason`）、最近处理时间；
- 顶部：总数说明 + 状态筛选 + 资源类型过滤 + 刷新；底部：分页（20/50/100）。
- 语义提示：表头下方明确「记录ID 为去重表主键，业务主键为动态/预约等业务ID」，避免混淆。
- 打开弹窗即加载，切换工作流或筛选条件时自动刷新。

## 5. 界面落点

| 位置 | 行为 |
| --- | --- |
| 工作流卡片 | 运行中展示进度条 + 计时 + 轮次/步骤；终态后保留最后一次快照（最终耗时） |
| 卡片操作栏 | 运行中「停止」；`last_run_status=interrupted` 时显示「继续运行」 |
| 运行记录弹窗 | 运行中行的「进度」列走 SSE 实时刷新；`interrupted && resumable` 行显示「可恢复」标签与「继续」按钮 |
| 编辑弹窗 | 「断点恢复」开关（默认关），说明至少一次语义与手动入口 |

## 6. 连接生命周期

- 订阅时机：卡片或弹窗出现 `status=running` 的运行；同一 `run_id` 只保留一条订阅。
- 关闭时机：收到终态帧、弹窗关闭、组件卸载、列表刷新后该运行已不在运行中。
- 断线：SDK 最多重连 2 次（1.5s 起）；仍失败则清掉本地进度并刷新列表，不弹错误提示。
- 终态后刷新一次列表，补齐 `execution_id`、错误信息等字段，并向父页面抛 `run-changed`。

## 7. 文案约定

- 开始运行：「已开始运行，进度见卡片与运行记录」（异步，不得再按同步结果判断成功/失败）。
- 成功：「「X」运行成功（成功 a / 失败 b / 共 n 步）」。
- 失败：「「X」运行失败：错误信息」。
- 中断：「「X」运行被中断，可在运行记录中继续运行」。
- 停止：「「X」已停止（成功 a / 失败 b / 共 n 步）」。
