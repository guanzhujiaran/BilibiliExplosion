# 爬虫推送开关管理页（CrawlerPushSwitchView）

## 背景

be-bilibili-crawler 的定时爬虫新增了「开始 / 结束」推送开关，默认**全关**：

- 部署级默认由环境变量 `CRAWLER_PUSH_START` / `CRAWLER_PUSH_END` 控制（逗号分隔爬虫名，`*` / `all` 全开）；
- 运行时可通过接口写入本地 JSON 文件（`{RUNTIME_DIR}/crawler_push_switch.json`），
  **文件里的爬虫优先于环境变量**，改完立即生效、重启保留。

现在需要一个管理页让管理员直接在界面上开关，不必改环境变量 + 重启。

前端调用的是 **be-message 的管理端代理**（前缀 `/api/v1/crawler/admin/push-switch`），
be-message 再内网转发 crawler 的 `/api/v1/background_service/BackgroundService/CrawlerPushSwitch*`：

| 方法 | 前端路径 | 用途 |
|---|---|---|
| GET  | `/api/v1/crawler/admin/push-switch` | 查询：文件内容 + 环境变量原值 + 每个爬虫的生效状态与来源 + 文件路径 |
| PUT  | `/api/v1/crawler/admin/push-switch` | body `{"items":[{"crawler_name":"GET_DYN","start":true,"end":false}]}`，按爬虫覆盖写入 |
| POST | `/api/v1/crawler/admin/push-switch/delete` | body `{"crawler_name":"GET_DYN"}`，删除该爬虫的文件配置，回退到环境变量 |

> **为什么经 be-message 而不是直连 crawler**：crawler 的 `/api/v1/background_service/*`
> 没有任何鉴权，只靠「网关不转发」保证不对公网开放；be-message 有 `AdminUser` 鉴权
> 与管理端审计日志，是项目既定的代理层（同一先例：LLM 配置页的 `/llm/*` 代理，
> 见 `be-message-service/app/services/infrastructure/crawler_llm.py`）。

响应字段（`data`）：

```ts
{
  state: { items: { crawler_name: string; start: boolean; end: boolean }[]; updated_at: number | null }
  env_start: string          // 环境变量原值，可能为空
  env_end: string
  state_file: string         // 开关文件落盘路径
  effective: { crawler_name: string; start: boolean; end: boolean; source: 'file' | 'env' }[]
}
```

## 前端需求

### 1. 位置与权限

- 新增页面 `src/views/admin/CrawlerPushSwitchView.vue`；
- 路由挂在 `ADMIN` 子路由下：

```ts
{
  path: 'crawler-push-switch',
  name: 'ADMIN_CRAWLER_PUSH_SWITCH',
  component: () => import('@/views/admin/CrawlerPushSwitchView.vue'),
  meta: { title: '爬虫推送开关', requiresAdmin: true, hidden: true }
}
```

- 页面内再兜一层 `v-if="!isAdmin"` → `el-empty`（与 `BiliCrawlerSummaryView.vue` 一致），
  `isAdmin = adminStore.status?.is_admin || adminStore.status?.is_root`。
- 入口同时挂到管理后台的两处（否则 `hidden: true` 的路由只能手敲 URL）：
  - `src/views/admin/AdminLayout.vue` 侧边栏「抽奖数据」组新增
    `{ name: 'ADMIN_CRAWLER_PUSH_SWITCH', title: '爬虫推送开关', icon: Switch }`；
  - `src/views/admin/AdminOverview.vue` 概览卡片新增同名条目
    （desc：`控制各爬虫「开始 / 结束」是否推送通知（默认全关）`）。

### 2. 页面结构

```
标题行：爬虫推送开关            [刷新]
说明：开关只影响「开始 / 结束」通知推送，不影响爬虫本身的执行；
      文件配置优先于环境变量，保存后立即生效、重启后保留。
提示条（el-alert，info）：
      环境变量：开始 = {env_start || '（空）'}，结束 = {env_end || '（空）'}
      开关文件：{state_file}
表格（el-table，default 尺寸，不传 size）
底部：[保存]  [全部恢复为环境变量]
```

### 3. 表格列

| 列 | 内容 | 宽度 |
|---|---|---|
| 爬虫 | `crawler_name`（等宽字体）+ `source` 标签 | min-width 260 |
| 开始 | `el-switch`（绑定本地草稿） | 120 |
| 结束 | `el-switch` | 120 |
| 当前生效 | 文案：`开始 开 / 结束 关` | 160 |
| 操作 | `el-button link`：`跟随环境变量` | 140 |

- `source === 'file'` → `el-tag type="success">文件配置`；`source === 'env'` → `el-tag type="info">环境变量`；
- 行内 `el-switch` 直接在本地 `rows` 上双向绑定，**不即时提交**；
- 「跟随环境变量」按钮：`Delete` 单行后重新 `GET` 刷新（该行回到 `source=env` 的取值）；
- 表格上方根据是否启用给行加视觉区分：启用（开始或结束为 true）的行 `class="crawler-push-row--on"`（仅做语义标识，不额外上色）。

### 4. 保存逻辑（只提交改动行）

```ts
const rows = ref<CrawlerPushRow[]>([])      // 来自 GET 的 effective
const dirty = ref<Set<string>>(new Set())

function onToggle(row: CrawlerPushRow) { dirty.value.add(row.crawler_name) }

async function save() {
  const items = rows.value
    .filter(r => dirty.value.has(r.crawler_name))
    .map(r => ({ crawler_name: r.crawler_name, start: r.start, end: r.end }))
  if (!items.length) return
  await crawlerPushApi.Set({ items })
  dirty.value.clear()
  await fetchState()   // 以服务端返回为准重刷
}
```

- **只提交改动行**：避免把所有爬虫一次性写进文件、导致以后环境变量全部失效；
- 保存成功 `ElMessage.success('已保存，立即生效')`；
- 失败提示后端 `msg`。

### 5. 接口接入

- 新建 `src/api/lottery_data/bili/crawler_push_api.ts`，**手写 `client`（不走生成的 Service）**：
  新接口尚未进入 hey-api 生成的 SDK，手写可立即生效（做法与 `src/api/community/sys_config_api.ts` 一致，
  待 SDK 重新生成后可平滑替换）；
- 直接 `import { client } from '@/api/bili_lottery_data/hey-api/client.gen'`，返回 `RootObject<T>`；
- 类型放 `src/models/admin/crawler_push_model.ts`。

### 6. 链路与权限（无需改网关）

```
前端 → 网关 /api/v1/crawler/admin/push-switch（既有 /api/v1 全量转发）
     → be-message（AdminUser 鉴权 + 审计日志）
     → httpx → crawler 23333 /api/v1/background_service/BackgroundService/CrawlerPushSwitch*
```

- 网关**不需要新增任何路由**（也不应把 crawler 控制面放上公网）；
- be-message 侧实现（照 `crawler_llm` 那套）：
  - `app/services/infrastructure/crawler_push.py`：httpx 客户端
  - `app/models/schemas/crawler_push.py`：请求/响应模型
  - `app/services/admin/crawler_push.py`：编排 + 参数校验 + 写操作审计日志
  - `app/api/crawler_push_admin.py`：三条路由，全部依赖 `AdminUser`

### 7. 规则遵循

- 全部 Tailwind 语义化主题类，禁止 `<style>` 与 `:style`；
- 不使用 `size="small"`，`el-switch` / `el-button` / `el-table` 一律默认尺寸；
- 功能元素带 BEM 语义 class 与 `id`：
  - 容器 `crawler-push-switch`
  - 表格 `crawler-push-switch__table`
  - 行 `crawler-push-row`
  - 开关 `crawler-push-switch__start` / `crawler-push-switch__end`（`id` = `crawler-push-{crawler_name}-start/end`）
  - 保存 `id="crawler-push-save"`，恢复全部 `id="crawler-push-reset-all"`
- 优先 `el-*` 组件（`el-table` / `el-switch` / `el-tag` / `el-button` / `el-alert` / `el-empty`）。

### 8. 「全部恢复为环境变量」

遍历当前 `rows` 逐条调用 `Delete`（后端无批量接口），全部完成后刷新。
按钮在「文件配置为空」时禁用（`state.items.length === 0`）。

## 验收

1. 进入页面默认全部关闭（环境变量为空、文件为空）；
2. 打开 `GET_OTHERS_LOT_DYN` 的「开始」，点保存 → 刷新页面仍为开，来源标签变为「文件配置」；
3. 点该行「跟随环境变量」→ 开关回到环境变量取值（默认关），来源变回「环境变量」；
4. 环境变量 `CRAWLER_PUSH_START=GET_DYN` 时，`GET_DYN` 行默认开、来源「环境变量」，
   页面上不点保存则不会被写进文件；
5. 「全部恢复为环境变量」后文件配置清空（`state.items` 为空，按钮变灰）；
6. 普通管理员可访问（`requiresAdmin`），非管理员直接 404；
7. `npm run generate`（typecheck）对本次改动文件无新增错误。
