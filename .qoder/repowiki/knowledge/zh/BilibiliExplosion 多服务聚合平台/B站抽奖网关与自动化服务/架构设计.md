模块以 `ExpressServerEnd/app.js` 为 HTTP 应用入口，经 `server.js` 启动并在监听前通过 `upstream_health_service` 检查上游依赖（be-message-service 不可用则拒绝启动）；中间件层统一挂载 helmet、cors、connect-timeout、JWT 校验 (`JwtModule`)、限流 (`Limiter`) 与请求日志，错误处理中间件将超时/上游错误映射为 504/502，业务校验错误统一返回 code 而非改变 HTTP 状态码。

路由按功能划分在 `routes/` 下（user、casdoor、ping、proxy、queues、do_lottery），由 `Controller/api/v1/*` 中的控制器接收请求，使用 express-validator 做入参校验后委派给 `Service/*` 下的领域服务；数据访问集中在 `DAO/`，其中 UserDao/UserRedisDao 已迁移为通过 `Service/mq/rpc_client` 调用 be-message 的 RPC 接口，仅 TUserActInfoLog 仍走本地 Sequelize + Postgres，模型定义位于 `Model/api/v1/*` 并继承 `base_model/base_api_model` 统一响应结构 `{code,data,msg,ttl}`。

除 HTTP 网关外，根目录 `index.js` 是独立的 Node 进程，作为定时调度器轮询上游获取抽奖动态文件，并通过事件总线 (`lib/helper/event_bus`) 协调 `木偶模块/puppeteer_lottery`（多账号动态/预约抽奖）、`直播模块/live_op`（直播弹幕发送）以及取关脚本；`ChatGPT/` 与 `刷视频播放时长/` 为辅助自动化脚本。

依赖方向：Controller → Service → (DAO/RPC) → 外部系统（Postgres、Redis、AMQP/RabbitMQ、Casdoor、B站 API、Puppeteer 浏览器）。
