模块以 `AdminLayout.vue` 作为路由容器，通过 `BiliSideNavLayout` 渲染侧边导航，并根据 `useRpaAdminStore` 与 `useMessageAdminStore` 的 `is_admin/is_root` 权限状态动态拼装导航分组（RPA 管理、消息管理端、动态管理端、用户管理端），再交由 `<router-view />` 加载具体审核页面。`AdminOverview.vue` 作为管理后台首页卡片入口，按相同权限逻辑生成可跳转卡片。各审核页（`AvatarAuditListView`、`FolderCoverAuditListView`、`MomentAuditListView`、`TopicAuditListView`、`ReportAdminView`）均为独立单文件组件，统一使用 `el-table-v2`（或 `el-table`）+ `LoadingWrap`/`EmptyState`/`PaginationBar`/`TimeText` 等消息域通用组件实现分页列表与审核操作；数据层直接调用 `@/api/notify/*` 与 `@/api/browser/hey-api` 生成的客户端 API，状态由 Pinia store（`rpa_admin.ts`）集中维护管理员身份并做 in-flight 去重。依赖方向单向：视图 → Pinia store → 自动生成 API 客户端，不互相引用。
