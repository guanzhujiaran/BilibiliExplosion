模块分为两层：
- base_axios 层：base_axios.ts 通过 axios.create 创建单例实例，并注册请求/响应拦截器——请求拦截器 AXIOS_REQ_AUTH_INJECTION 从 Pinia store（user_nav、locale）注入 x-bili-* 鉴权头与 Accept-Language；响应拦截器 AXIOS_RES_INJECTION 将后端 RootObject {code, msg, data, ttl} 扁平化到 response 上，非 0 时调用 apiErrorHandler。
- error_handler.ts 提供 ApiErrorHandler 单例，统一标准化错误（Axios 错误、网络错误、业务错误），支持 showToast / emitError / customHandler 三种输出通道；withErrorHandler 高阶函数用于包装方法自动检查 result.code。
- api_redirect_handler.ts 提供按 URL pattern 和 errorCodes 条件触发的跳转策略（含 fingerprintError、authError、serverError 等预设），结合 Element Plus 弹窗与 vue-router 完成用户确认后的导航。
- base_api.ts 定义 BaseApi 基类，子类通过 path + _get/_post/_getWithError/_postWithError 组合发起请求，复用错误处理。
- account/ 与 user/ 为具体业务 API 类：account_api.ts 直接调用 hey-api 生成的 client；user_api.ts 通过 adapt + businessHandler 将 hey-api 返回适配为统一的 BusinessResponse，并在 Nav 等方法中保留原始 response/error 以区分网络故障与业务失败码（如 -101）。user/utils.ts 的 isLogin 利用 Nav 的 fields 风格响应实现登录态检测与本地缓存同步。
依赖方向：业务 API → base_axios（错误处理/重定向）→ Pinia store / Vue Router / Element Plus，业务 API 之间无相互依赖。
