模块按职责拆分为两个子目录：`app/models/workflow/models.py` 集中定义所有 API 层的 Pydantic/SQLModel 请求与响应（Workflow、CompositeAction、Plugin、ActionExecute 等），不包含数据库表映射；`app/services/execution/crud_service/` 下每个文件对应一个业务实体的 `*CrudService` 类，封装对 `app.models.database.workflow.models` 中数据库模型的异步查询。

- 数据访问通过 `DatabaseSessionManager.async_session()` 管理会话，所有方法均为 `@staticmethod` 或 `@classmethod`，并在模块末尾导出单例实例（如 `workflow_crud_svr`）供上层调用。
- 实体划分：`workflow_crud.py` 管理 `UserWorkflow` 及其关联 `WorkflowPluginRelation`；`action_crud.py` 管理 `CompositeActionModel`、`TagModel`、`CompositeActionTagLink`，并提供步骤中嵌套 `ca_` 操作的递归校验与详情注解能力；`plugin_crud.py` 管理 `UserPlugin`；`community_crud.py` 处理跨实体的举报（`ResourceReport`）审核流程；`action_log_crud.py` 独立维护执行日志的写入、分页、统计与过期清理。
- 依赖方向单向向下：CRUD 服务 → 数据库模型 → SQLModel/SQLAlchemy；API 模型仅被 CRUD 服务用于参数描述，不反向依赖服务。
- 权限与可见性通过统一的 `filter_type`（private/public/community/verified/all）在查询时拼接 `mid == str(mid)` 与 `is_public` 条件实现。
