本模块由三个并列子目录构成，职责清晰且相互独立：
- `admin/`：面向管理端的业务服务。`message_admin.py` 通过 `MessageAdminService` 在 `msg_admin` 表上实现仅 root 可授予/撤销的消息管理端权限（使用 `sanitize_permissions` 剔除 root 专属权限），并提供分页列表与状态查询；`report.py` 的 `ReportService` 是纯协调器，依赖 `interaction_actions.base_biz.BaseBiz` 注册表按 `(biz_type, biz_id)` 分发到具体资源类，统一编排「校验→落库→阈值→审核→通知」流程，不感知任何资源差异。
- `cleanup/`：按领域拆分的注销删除服务，每个 `cleanup_<domain>.py` 暴露统一的 `delete_all_by_uid(session, uid)` 类方法，负责清除 be-message MySQL 中该领域的全部数据（动态、评论、私信、关注、收藏、通知、事件、举报、misc、pptr），调用方只负责按依赖顺序编排。
- `infrastructure/`：横切基础设施。`jwt_service.py` 签发/解码 HS256 JWT（载荷含 user_name/uid/level/role，15 天有效期，验签仍由 pptr 网关负责）；`geo_ip.py` 基于 MaxMind GeoLite2 mmdb 懒加载单例解析 IP 属地与经纬度，失败静默降级；`rpa_rpc.py` 与 `lottery_rpc.py` 封装 `bili_common.rpc.client.RpcClient`，以 RabbitMQ 为传输对 RPA-Browser/be-bilibili-crawler 发起同步 RPC，所有外部调用均为弱依赖，超时/未连接/异常均返回 None 或 False 并记录日志，避免影响主流程。
依赖方向：上层 admin/cleanup 依赖 infrastructure 提供的通用能力，但三者之间无横向耦合，均通过 `app.core.database.SessionDep` 与 `app.models.db.*` 模型交互。
