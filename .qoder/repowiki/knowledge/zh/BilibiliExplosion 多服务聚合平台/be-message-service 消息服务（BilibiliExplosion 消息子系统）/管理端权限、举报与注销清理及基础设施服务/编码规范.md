- 每个 cleanup 领域模块对外统一暴露 `delete_all_by_uid(session, uid)` 类方法，由调用方按依赖顺序编排调用，模块内部不持有事务边界。
- RPC 客户端采用「弱依赖」模式：构造时创建 `RpcClient`，调用前检查 `connected`，超时/异常一律捕获并返回 None/False，仅记录 loguru 警告日志。
- 基础设施服务以模块级全局单例暴露（如 `rpa_rpc_client`、`_rpc_client` + `get_lottery_rpc_client()`），避免重复建立连接。
- 管理类服务统一使用 `@staticmethod` 的类方法组织，并通过 `SessionDep` 注入 SQLModel 会话，不自行管理 session 生命周期。
- 举报协调器通过 `BaseBiz._registry` 与 `get_biz` 按 `biz_type` 分发资源差异，自身不出现 `if/elif` 分支处理不同资源类型。
- 对外 API 返回值遵循「失败即降级」原则：GeoIP 解析失败返回 `poi="未知"`，RPC 失败返回空结果，保证上游主流程不被中断。
