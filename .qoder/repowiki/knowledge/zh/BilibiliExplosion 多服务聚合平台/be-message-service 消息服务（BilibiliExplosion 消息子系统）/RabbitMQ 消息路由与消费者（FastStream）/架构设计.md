模块分为两层：`app/mq/` 是 FastStream 的 RabbitMQ 接入层，`router.py` 通过 `RabbitRouter` 创建单一 `broker` 实例并管理其生命周期（`after_startup` 启动调度器、`on_broker_shutdown` 停止调度器），所有消费者和 RPC 处理器都注册到该 broker；`app/consumers/` 是纯业务处理函数，按领域拆分为 comment/dm/external_push/deactivate/interaction_view/retry 等文件，被 `mq/consumers/` 下的胶水模块通过 `@router.subscriber(...)` 装饰器绑定到具体队列。

依赖方向单向：`mq/consumers/*` → `app/consumers/*`（调用业务 handler）→ `app.services.*`（领域服务）+ `app.core.broker`（共享 broker/exchange/queue 常量）。RPC 端点集中在 `rpc_external_push.py`（`message.push.rpc.*`）和 `rpc_pptr_user.py`（`message.pptr.rpc.*`），均使用 `bili_common.models` 中的统一参数/响应模型并通过 `push_rpc_routing_key_for` / `pptr_routing_key_for` 生成 routing key，由调用方（be-gateway、RPA-Browser、爬虫等）经 amqplib 同步调用。

消费者采用「订阅即注册」副作用模式：`mq/consumers/__init__.py` 仅 import 各子模块以触发装饰器注册，再由 `app/main.py` 一次性 import 完成全部绑定。重试策略通过 `consumers/retry.py` 读取 RabbitMQ `x-death` 头统计重投次数，避免无限 requeue 死循环。
