模块按职责拆分为五个子模块并通过 `__init__.py` 统一对外暴露：
- `comment.py`（CommentService）：评论写路径，包含发布（add）、删除（delete）、置顶（set_top）、举报（report），在一个事务内原子写入索引表 `msg_comment_index`、正文表 `msg_comment_content`、评论区计数 `msg_comment_subject` 及楼中楼 `rcount`，并使用数据库侧 `UPDATE ... SET c = c + 1` 避免并发丢更新。
- `comment_action.py`（CommentActionService）：点赞/点踩/取消，基于 `uq(rpid, mid)` 保证幂等，并在同一事务内增量重算冗余列 `hot_score`。
- `comment_read.py`（CommentReadService）：列表/详情/计数/楼中楼展开，严格遵循「SQL 次数与返回条数无关」的常量查询约束，通过先取 ID 再按 IN 批量回捞正文、用户快照、互动态的方式避免 N+1。
- `comment_audit.py`：基于进程内 DFA Trie 的词库敏感词匹配，命中高危直接 REJECTED、疑似置 AUDITING，词库加载失败时降级放行。
- `comment_admin.py`（CommentAdminService）：管理端审核队列、状态变更（通过/驳回/下架/恢复）、明文 IP 查看、全局统计；状态翻转时同步评论区冗余计数与动态 `commentCount`，并通过 D6 补偿通道补发此前跳过的回复/@通知。
依赖方向单向向外：本包依赖 `app.models.db`（SQLModel 模型）、`app.core.*`（配置/分片/会话）、`app.services.message.insite.*`（事件/通知弱依赖）、`app.services.user.follow`（拉黑校验）和 `app.services.moment.moment_stat`（动态统计），不被其他业务服务反向依赖。
