测试按业务域划分为多组独立 pytest 文件：`test_phase_b_smoke.py` 覆盖系统通知/事件提醒/私信/设置/活跃度；`test_comment_crud.py`、`test_comment_phase23.py`、`test_comment_count_sync.py` 覆盖评论读写与计数回写；`test_moment_publish.py`、`test_moment_feed.py`、`test_moment_interaction.py`、`test_moment_topic*.py`、`test_moment_audit.py` 覆盖动态发布、Feed、互动、话题与审核；`test_push_rpc.py`、`test_push_channels.py`、`test_rpc_notify.py` 验证站外推送 RPC 契约；`test_avatar*.py`、`test_folder_cover_audit.py`、`test_report.py`、`test_user_deactivate.py`、`test_space_info.py`、`test_edgerank.py`、`test_str_int_route_params.py` 覆盖其他子模块。

每个测试通过 `@pytest.fixture(autouse=True)` 在自身事件循环中重建 SQLAlchemy async engine 并注入 `app.core.database` 模块级单例，确保用例间隔离；所有用例使用独立的 mid / oid 区间（如 `_OID_BASE = 882_000_000_000`、`M = {...}`）并通过 `_cleanup` 或显式 SQL 删除保证幂等。

数据准备采用两种策略：一是直接操作 `app.models.db` 模型写入 `TMoment`、`DmMessageIndex`、`NotifyMessage` 等表；二是通过 `seed_biliopus.py` 直连 `biliopusdb`（同一 MySQL 实例的不同库）拉取真实抽奖动态正文与话题作为种子数据，使测试贴近线上形态。

外部依赖（RabbitMQ、分片库、第三方推送渠道）在本机不可用，测试通过直接调用 Service 层方法 + 打桩 `publisher.publish_dm_content`、`DmContentService` 等方式仅验证主库索引与核心逻辑。
