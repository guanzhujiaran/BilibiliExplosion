本模块由四个独立的 FastAPI `APIRouter` 组成，分别挂载到 `/api/v1/message/notify`、`/api/v1/message/event`、`/api/v1/report`、`/api/v1/message/setting` 路径下，每个文件即一个业务域的路由入口。
- 认证与权限：用户侧接口通过 `RequiredUser` 依赖注入当前登录态；管理员侧接口通过 `AdminUser` 依赖注入 root/管理员身份，二者均不自行校验 token，完全依赖上游网关注入的 `x-bili-*` 请求头。
- 数据访问：所有 handler 通过 `SessionDep` 获取数据库会话，再调用 `app.services.message.insite.*`（NotifyService、BaseEvent、ActivityService、SettingService）或 `app.services.admin.report.ReportService` 执行业务，HTTP 层仅负责参数解析、响应包装与异常映射。
- 响应规范：统一使用 `StandardResponse[T]` 作为返回模型；业务失败通过抛出 `ValueError` 在路由层捕获并转为 `code=400` 的标准响应。
- 职责边界：event.py 中的 `/report` 面向内部服务（无需登录，mid 由请求体指定），其余接口均需登录态；notify.py 区分用户侧（pull/list/system/unread/delete）与管理员侧（admin/create/update/revoke/admin/list）两套子集；report.py 将动态/评论/用户空间三类举报收敛为统一入口，并通过 `biz_type`+`biz_id` 区分来源。
