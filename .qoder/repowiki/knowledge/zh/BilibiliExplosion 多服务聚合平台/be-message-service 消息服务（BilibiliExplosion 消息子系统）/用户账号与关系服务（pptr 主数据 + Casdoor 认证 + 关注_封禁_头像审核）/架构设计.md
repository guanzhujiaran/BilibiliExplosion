模块以 `account/base.py` 中的 `PptrUser` 领域对象为核心，通过子类化组合出不同权限角色：`comment_admin.py`、`dm_admin.py`、`user_governance.py` 各自定义一组 `ROLE_PERMISSIONS` 并叠加封禁/评论/私信管理能力，`root.py` 的 `RootAdminUser` 用多重继承聚合全部权限。
- 数据访问层：所有读/写均通过 SQLModel 直接操作 pptr Postgres 的 `TUserInfo/TUserDetail/TUserVip/TUserLevel` 四表（`_base_select` 统一外联 + 软删过滤），跨库写入（如封禁落 be-message 的 `msg_user_ban`、头像审核落本地 MySQL）采用独立会话，失败仅告警不回滚主事务。
- 认证网关：`casdoor_service.py` 提供 OAuth 授权码换 token、refresh_token、管理员 token 进程级缓存、按 user_name/email/access_token 三种模式查询 Casdoor 用户信息，并把 access_token 持久化到 `TUserInfo.pwd`。
- 独立业务服务：`follow.py`（关注/拉黑，存于 `msg_user_follow`）、`avatar_audit.py` / `folder_cover_audit.py`（先审后发，状态机驱动）、`avatar_check.py`（头像校验）均为无状态 Service 类，依赖 `PptrUser` 获取展示信息但不回写主数据。
- 依赖方向：本模块向上被 API 路由调用，向下依赖 `app.models.*`、`app.core.database`、`bili_common.deps.permissions`，不反向依赖上层路由。
