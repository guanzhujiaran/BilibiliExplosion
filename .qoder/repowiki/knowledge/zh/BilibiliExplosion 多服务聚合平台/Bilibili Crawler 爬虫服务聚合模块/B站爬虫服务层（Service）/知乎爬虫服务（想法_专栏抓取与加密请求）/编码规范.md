- 所有网络请求通过统一的 `__request` 包装器重试，遇到 40352/10003 等错误码时自动 sleep 后重试。
- 请求头动态构造：先通过 `_get_dc_0` 获取 d_c0 cookie，再用 `zhi_hu_encrypt.encode(d_c0, url_path+url_params)` 生成 `x-zse-96` 注入 headers。
- 业务状态（已抓取的 pin id、用户列表、时间戳）以 JSON/TXT 文件形式持久化在模块相对路径的 `records/` 目录下，启动时读取、结束时写回。
- 抓取到的 Pin 数据统一建模为 `PinDetail` 对象，并通过 `PinDetailType` 枚举标记来源类型（moment/zhuanlan）。
- Playwright 操作通过 `expect_response` 捕获目标 API 响应后再进行滚动翻页，避免直接构造 URL 参数。
