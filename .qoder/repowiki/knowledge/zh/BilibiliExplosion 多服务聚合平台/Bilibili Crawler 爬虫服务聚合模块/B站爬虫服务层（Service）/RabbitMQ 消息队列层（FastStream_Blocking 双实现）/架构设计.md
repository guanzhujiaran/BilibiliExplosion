模块按职责划分为四个子目录：
- `base/`：底层抽象与通用客户端。`BasicMQ.py` 提供基于 `pika.BlockingConnection` 的同步服务端基类（连接、队列声明、publish/consume），被 `MQServer/Ipv6ChangeMQServer.py` 继承用于 IPv6 变更通知；`BasicAsyncClient.py` 提供基于 `pika.adapters.asyncio_connection.AsyncioConnection` 的 `BasicMessageReceiver`/`BasicMessageSender`，内置断线重连、topic 路由拼接、msgpack 编解码与 `_mq_retry_wrapper` 重试装饰器。
- `base/MQClient/`：业务级 FastStream 客户端。`base.py` 定义 `BaseFastStreamMQ` 抽象及全局 `RabbitRouter`、`RabbitExchange('bili_data')`，并集中声明各业务队列的 `MQPropBase`（queue/routing_key/exchange 三元组）；`BiliLotDataPublisher.py` 通过 `publisher_producer(mq_props)` 工厂生成带 Redis 待发送缓存（`RedisObj`）和无限重试的异步发布函数，暴露 `pub_official_reserve_charge_lot`、`pub_prize_extract` 等静态方法；`BiliLotDataFastStream.py` 中每个 `BaseFastStreamMQ` 子类对应一个消费者（如 `OfficialReserveChargeLot`、`UpsertOfficialReserveChargeLot`、`BiliVoucher` 等），统一通过 `handle_exception` 记录日志并 `nack`；`PrizeExtract.py` 将两条入库队列（biliopusdb / dyndetail）的处理逻辑抽为共享的 `process_prize_extract`，使用 Redis 分布式锁 + Lua 信号量限制大模型调用并发。
- `message/`：面向 message-service 的推送消息发布通道，复用同一 `router.broker` 投递到独立 exchange/queue。
- `utils/RabbitmqPubCacheRedis.py`：以 Redis Hash 存储待发送消息（`CachedMessage`），配合 `BiliLotDataPublisher.retry_pending_messages` 实现 MQ 不可用时的持久化重试。
依赖方向：业务消费者 → `BaseFastStreamMQ` → `router.broker`；发布者 → `publisher_producer` → `redis_obj` 缓存 → `router.broker`；所有配置来自 `CONFIG.RabbitMQConfig`，交换名/队列名/路由键集中在 `Models.MQ.BaseMQModel` 枚举中。
