- 每个业务队列在 `base/MQClient/base.py` 中以 `MQPropBase(queue_name=QueueName.X, routing_key_name=RoutingKey.X, exchange=exch)` 形式集中声明，消费者与发布者均通过该实例绑定，避免硬编码字符串。
- 消费者统一继承 `BaseFastStreamMQ` 并实现 `async def consume(body, msg)`，异常处理通过统一的 `handle_exception(module_name, e, params, msg)` 记录日志、推送告警并 `msg.nack()`。
- 发布者方法统一使用 `@_mq_retry_wrapper(max_retries=-1)` 装饰器实现无限重试，并在失败时通过 `a_push_error` 上报运行异常。
- 发布流程先写入 Redis 待发送缓存（`redis_obj.add_pending_message`），成功后再删除，失败后可由 `retry_pending_messages` 批量重发，保证消息不丢失。
- 大模型提取入口 `process_prize_extract` 采用固定四步流程：Redis 去重锁 → 查库判重 → Lua 信号量限流 → 调用提取并写库，并发满时重新入队回原队列。
- 消息路由键支持 `extra_routing_key` 后缀拼接（`ROUTING_KEY + '.' + extra_routing_key`），topic 模式下消费者自动追加 `.#` 通配符。
