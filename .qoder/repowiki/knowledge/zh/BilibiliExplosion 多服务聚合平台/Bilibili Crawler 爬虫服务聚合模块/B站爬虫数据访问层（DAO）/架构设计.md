模块按存储后端划分为两类 DAO：
- MySQL 访问：以 `base/sqlHelperBase.py` 中的 `SqlHelperBase` 为基类，每次实例化通过 `sqlalchemy_session_factory` 创建独立的 Engine 与 `async_sessionmaker`，实现连接池隔离；所有写操作统一走带重试包装的 `execute(stmt)` 方法。具体业务 DAO `biliLotteryStatisticSqlHelper.py` 中的 `LotteryDataStatisticSqlHelper` 继承该基类，使用 SQLAlchemy Core/ORM 对 `BiliUserInfo`、`BiliAtariInfo` 等模型执行插入、批量写入（含死锁重试）和分页查询。
- Redis 访问：各文件（`IpInfoRedisObj`、`commStorageRedisObj`、`lotDataRedisObj`、`biliLotteryStatisticRedisObj`）均继承 `Utils.redisTool.RedisManager.RedisManagerBase`，并通过内部 `RedisMap` 枚举集中声明 key 模板，配置来自 `CONFIG.database.*`，最终在模块级暴露单例对象（如 `ip_info_redis`、`lottery_data_statistic_sql_helper`）供上层调用。
依赖方向单向：DAO 仅依赖 `CONFIG`、`Models`、`Utils` 与第三方库，不反向被业务层以外的模块引用，构成爬虫的数据出口边界。
