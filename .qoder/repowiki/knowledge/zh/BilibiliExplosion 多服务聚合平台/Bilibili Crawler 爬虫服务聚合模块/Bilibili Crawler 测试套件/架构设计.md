测试模块以 `conftest.py` 为全局入口：在 `pytest_configure` 中注入 MySQL/Redis/RabbitMQ/LLM 等环境变量默认值，并构造一个最小 FastAPI app（仅注册业务 router，跳过需要 broker 连接的 faststream MQ 路由），通过 `httpx.AsyncClient` + `ASGITransport` 提供无网络 HTTP 客户端。

测试按职责拆分为独立文件：
- `test_captcha.py` / `test_common_router.py` / `test_other_routers.py`：针对 `/api/v1/captcha` 等 HTTP 端点的请求/响应断言，内部用 `unittest.mock` 替换下游 service。
- `test_mq.py`：分层覆盖 MQ 核心链路——消息模型序列化往返、`publisher_producer` 写 Redis 待发缓存→broker.publish→清缓存、消费者 ack/nack 异常兜底、`retry_pending_messages` 重发；集成用例由 `RUN_MQ_INTEGRATION=1` 开关启用，使用 FastStream `TestRabbitBroker` 做内存路由。
- `test_prize_extract_flow.py`：用 SQLite 内存引擎 + 自定义 `TestSqlHelper` 替换真实 `SqlHelper`，验证从 MQ Handler → Consumer → LLM 提取 → 入库的完整链路，并通过 `AsyncExitStack` 集中 patch 提取器与 Redis 锁/信号量。
- `_test_crawler.py`：定义 `TestCrawler`（继承 `UnlimitedCrawler`）模拟 normal/error/timeout 三种任务，配合 `StatsPlugin` 验证重试、超时与统计插件行为。
- `grpc_test.py` / `test_chatgpt.py` / `test_background_service.py` / `test_lottery_data.py` / `test_get_other_lot_main.py`：分别对 gRPC 调用、ChatGPT 接口、后台服务、抽奖数据抓取等进行单元测试。

共享数据集中在 `fixtures/`（Bilibili 动态/回复 JSON 样例）和 `test_data/prize_extract_cases.json`（抽奖提取用例）。所有测试均通过 `sys.path.insert` 将项目根目录与 `Service/GrpcModule/Grpc/GrpcProto` 加入导入路径，确保能直接 import 被测模块。
