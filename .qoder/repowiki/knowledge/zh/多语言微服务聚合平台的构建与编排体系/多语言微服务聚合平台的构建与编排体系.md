## 1. 整体方案

仓库采用 **Docker Compose 单文件编排** + **多阶段 Dockerfile** 的混合构建模式，将 Python（FastAPI）、Node.js（Express/Vue3）、Go、Java（Spring Boot）四种语言的服务统一在 `docker-compose.yml` 中编排启动。根目录的 `Makefile` 提供 `start / stop / restart / logs / down / clean / submodule-init / update` 等命令，封装 `docker-compose` 调用；`.github/workflows/docker-publish.yml` 负责在 push/PR 到 main 分支时通过 GitHub Actions 使用 Buildx 构建镜像并推送到 ghcr.io，同时用 cosign 签名镜像。

## 2. 关键构建文件

- **根级编排与入口**：`docker-compose.yml`（定义 etcd/minio/milvus/mysql/redis/rabbitmq/postgres/casdoor/nginx/llama_cpp/unidbg/gateway/rpa-browser/be-message-service/be-bilibili-crawler 等服务）、`Makefile`、`dc-dev.yml`（开发专用 compose 片段）、`pm2.app.js`（本地 PM2 进程管理 IPv6 代理）。
- **Python 服务统一镜像**：`Dockerfile.mono` 定义 `base → crawler/rpa/message/default` 四个多阶段 target，共享 Debian Bookworm + uv + Node.js + OpenCV 依赖层；三个 FastAPI 子项目（`be-bilibili-crawler`、`RPA-Browser`、`be-message-service`）通过 `docker-compose build --target <crawler|rpa|message>` 复用同一基础镜像。
- **各子服务独立 Dockerfile**：`be-gateway/Dockerfile`（node:24-alpine，dev/prod 双 stage）、`go-proxy-ipv6-pool-auto/Dockerfile`（golang:1.25 + ndppd）、`unidbgSpringBoot/pom.xml`（Spring Boot Maven Plugin 直接生成 `unidbg-springboot-samsclub` 镜像）。
- **前端构建**：`Vue3FrontEndDemoExercise/package.json` 通过 Vite (`vite build --mode prod`) 产出静态资源，由 nginx 容器挂载 `docker_vol/nginx/html` 提供。
- **CI**：`.github/workflows/docker-publish.yml` 触发条件为 push/PR to main，且 push 需 commit message 包含 `[deploy]`；使用 `docker/build-push-action@v5` 配合 `docker/metadata-action` 打 tag，缓存走 `type=gha`。

## 3. 架构与约定

### 3.1 多阶段镜像分层
`Dockerfile.mono` 将公共系统依赖（g++/gcc/nodejs/npm/pkg-config/libssl-dev/git/libgl1-mesa-glx/libglib2.0-0/libsm6/libxext6/libxrender-dev/libgomp1）放在 `base` 层，再派生 `crawler`、`rpa`、`message` 三个 target。每个 target 内部遵循“先安装依赖（lock 文件 bind 挂载，源码未变更不失效该层）→ 再拷贝源码 → 最终 uv sync”的两段式结构，最大化利用 Docker 层缓存。

### 3.2 依赖管理
- Python：统一使用 `uv`（`uv.lock` + `pyproject.toml`），并通过 `UV_NO_EDITABLE=1` 将 `bili-common` 作为路径依赖以非 editable 方式安装，避免运行时依赖源码目录。
- Node.js：`be-bilibili-crawler` 和 `be-gateway` 使用 npm（配置 npmmirror 源），`Vue3FrontEndDemoExercise` 声明 `packageManager: pnpm@11.14.0`，但实际构建脚本仍走 vite 默认流程。
- Go：`go mod download` 后 `go build -o main .`，GOPROXY 设为 `https://goproxy.cn,direct`。
- Java：Maven 通过 Spring Boot Maven Plugin 的 `<image>` 目标直接输出镜像，版本固定为 `unidbg-springboot-samsclub`。

### 3.3 服务间通信与环境变量
所有跨服务连接通过 `docker-compose.yml` 中的 `environment` 注入，如 `MYSQL_HOST=mysql`、`RABBITMQ_URL=amqp://${RABBITMQ_USER}:${RABBITMQ_PASSWORD}@rabbitmq:5672/`、`MESSAGE_SERVICE_HOST=be-message-service`、`CASDOOR_ENDPOINT=http://fastapi-casdoor:8000` 等；敏感信息统一从宿主机 `.env`（`MYSQL_PASSWORD`、`POSTGRES_PASSWORD`、`RABBITMQ_*` 等）注入，容器内仅持有变量名。

### 3.4 数据持久化
所有外部依赖（MySQL、Redis、RabbitMQ、Postgres、Milvus、MinIO、etcd、Nginx、GeoIP mmdb、Llama 模型）的数据目录均通过 `./docker_vol/<service>/...` 绑定挂载，保证容器销毁后数据不丢失。

### 3.5 健康检查
对关键基础设施（etcd、minio、milvus）和 `be-message-service` 定义了 `healthcheck`，其中消息服务通过访问 `/health` 端点校验 broker 连通性，返回 503 即视为不健康。

## 4. 约定与约束

- **服务启停统一通过 Makefile**：`make start` 等价于 `docker-compose up -d`，`make start-excluding-fastapi` 跳过 fastapi 相关服务以便单独调试；`make logs [SERVICE]` 支持按服务过滤日志。
- **首次克隆必须执行 `make submodule-init`**：仓库使用 git submodule，初始化后再同步远端最新代码用 `make update`。
- **Python 服务运行端口固定**：crawler 暴露 23333、rpa-browser 暴露 28000、message-service 暴露 18739，均由 `Dockerfile.mono` 对应 target 的 `EXPOSE` 与 `CMD` 指定。
- **Gateway 与 RPA 使用源码热重载**：`docker-compose.yml` 中将源码目录以 volume 形式挂载到 `/app`，便于开发时修改即时生效。
- **IPv6 代理池通过 PM2 本地托管**：`pm2.app.js` 以 `ipv6_server` 名称拉起 `go-proxy-ipv6-pool/go-proxy-ipv6-pool` 二进制，错误/输出重定向至 `/dev/null`。
- **CI 发布需显式标记**：push 到 main 分支的镜像推送仅在 commit message 包含 `[deploy]` 时触发，避免误发。
- **网络启用 IPv6**：compose 顶层 `networks.default.enable_ipv6: true`，为 IPv6 动态出口代理池提供网络能力。
- **镜像加速**：Python base 使用 `ghcr.nju.edu.cn/astral-sh/uv` 国内镜像，apt 源切换为阿里云，npm registry 指向 npmmirror，Go GOPROXY 指向 goproxy.cn，LLM 模型下载走 hf-mirror.com。
